# 自治体詳細ページのナビゲーション設計（タブ／セクションナビ）

デザインシステム統一のモックにあった「概要／データ／比較／ランキング／詳細情報」のタブについて、
現状の情報構造を棚卸しし、実装方式を比較して推奨案をまとめた検討メモ。**この文書時点では未実装。**

対象: `app/area/[pref]/[city]/page.tsx`（約770行）＋ `components/area/*`（11ファイル）＋ `app/area/[pref]/[city]/area-detail.css`

## 3. 実装方式の比較

| | A. 真のタブ（`hidden` 切替） | **B. セクションナビ（推奨）** | C. B ＋ 一部折りたたみ |
|---|---|---|---|
| 見た目 | モックに最も忠実 | モックのタブバーと同じ | 同左 |
| 初期表示の高さ（PC） | 700〜1,300px | 5,882px（変わらず） | 約3,000px |
| 初期表示の高さ（SP） | 730〜2,330px | 9,025px（変わらず） | 約5,400px |
| 本文リンク61〜77本の可視性 | 初期タブ内のみ（十数本） | 全て可視 | 全て可視（折りたたみ内も DOM） |
| FAQ ↔ `FAQPage` 構造化データ | **前提が崩れる**（後述） | 維持 | 維持 |
| JS 無効時 | 先頭タブのみ表示 | 素のアンカーとして機能 | 機能する |
| 新規クライアントコンポーネント | 必須（本文で初のstate） | 任意（アクティブ表示のみ） | 任意 |
| GA4 のスクロール深度指標 | 不連続になる | 連続 | ほぼ連続 |
| 実装コスト | 大（page.tsx の再編成） | 小 | 中 |

### A（真のタブ）のSEO上の懸念

1. **FAQ の可視性要件。** `lib/faq.ts` の冒頭に「可視テキストと `FAQPage` 構造化データの両方で同じソースを使い、
   内容を一致させる（Google の FAQ は**回答がページ上に可視であることが要件**のため）」と明記されている。
   実際 `page.tsx` は同じ `buildFaq()` の戻り値を JSON-LD と可視 `details` の両方に使っている。
   FAQ を初期非表示のタブに入れると、この設計前提から外れる。
   現在の `<details>`（初期閉じ・DOM内）は Google が明示的に許容する形式だが、`hidden` なタブパネルはより踏み込んだ扱いになる。
2. **内部リンクの比重。** このページは回遊導線（近隣自治体・似たエリア・ランキング14種）が集客設計の中核で、
   1ページあたり61〜77本の内部リンクを持つ。`hidden` 内のリンクは HTML には存在するが、
   可視リンクと同等に評価される保証はない。
3. **前例。** `components/home/PrefRegionPicker.tsx` のコメント（6〜9行目）は、47県のリンクを
   「クロール可能にするため全パネルを DOM に残す（`display:none` にせず `hidden` 属性）」と明記している。
   つまりこのコードベースは既に「隠すことのリスク」を意識して設計されている。

### B（セクションナビ）を推奨する理由

モックのタブバーが与える価値の大部分は「**この長いページに何があるか一覧でき、そこへ飛べる**」ことで、
それは**コンテンツを隠さなくても得られる**。SEO 上の不確実性をゼロにしたまま、
モックの見た目と回遊性の改善を両取りできる。

## 4. B の設計（着手する場合の設計図）

### 4-1. マークアップ

```
PageShell
 └ .ad-root
    ├ Breadcrumb
    ├ header.ad-hero                       ← タイトル・スコア
    ├ nav.ad-secnav  (sticky)              ← ★新規
    │   概要 | データ | 比較 | ランキング | 詳細情報
    ├ section#overview  … 特徴 / 総評 / データで見る / KPI
    ├ section#data      … 詳細データ
    ├ section#compare   … 回遊カード群
    ├ section#ranking   … ランキング14種
    └ section#details   … FAQ / 出典 / 支援 / CTA
```

- `components/area/Section.tsx` は現在 `id` を受け取らない（`Reveal.tsx` も同様）。
  両方に `id?: string` を足す（`Reveal` は `as` で `section` を出せるので、`id` を透過させるだけ）。
- アンカーは5つのグループ先頭セクションに付ける。既存のセクション分割は変えない。

### 4-2. `components/area/SectionNav.tsx`（新規・クライアント）

- `<nav aria-label="このページの目次">` ＋ `<a href="#overview">` 等。**素のアンカーなので JS 無効でも動く。**
- `IntersectionObserver` で現在位置のリンクに `aria-current="true"` を付けるだけ（表示の切替はしない）。
- キーボード操作は通常のリンクなので追加実装不要。`role="tablist"` は使わない（タブではないため、
  スクリーンリーダーに誤った期待を与えない）。

### 4-3. CSS

- `.ad-secnav { position: sticky; top: 0; z-index: 5; background: var(--surface-strong); border-bottom: 1px solid var(--border); }`
  `.site-header` は非sticky なので競合しない。SP では横スクロール可（`overflow-x: auto`）。
- 各アンカー先に `scroll-margin-top: 56px`（ナビの高さ分）。
- チップの見た目は `globals.css` の `.home-region-tab`（`aria-selected` で塗り分け）を流用し、
  `aria-current="true"` セレクタで同じ配色にする＝トップのタブと同一の部品に見える。
- `@media (prefers-reduced-motion: reduce)` で `scroll-behavior: auto`。

### 4-4. 計測

`lib/analytics.ts` の `track()` を再利用して `track("select_section", { section, municipality_code })` を送る。
どのセクションが実際に使われているかが分かれば、次にどこを削る／伸ばすかの判断材料になる。

### 4-5. 想定工数

`Section`/`Reveal` への `id` 追加、`SectionNav` 新規、CSS 約40行、`page.tsx` のグルーピング。
**半日程度**。`page.tsx` の差分はセクションを5つの `<div id>` でくくるだけで、
既存のコンポーネント・データ取得・JSON-LD には触らない。

## 5. C（B ＋ 一部折りたたみ）を足す場合

高さの上位2ブロックを `details` にするだけで大きく短縮できる。`details` は
FAQ（`.ad-faq-item`）・出典（`.ad-sources`）・ランキングページ（`.rk-faq-item`）で既に使っている**ハウスパターン**で、
Google も明示的に許容する形式。

| 折りたたむ候補 | PC 短縮 | SP 短縮 |
|---|---|---|
| ランキングで比較（14枚） | −620px | −660px |
| 回遊カード群（4〜6セクション） | −840px | −2,200px |
| 合計 | 約 −1,460px | 約 −2,860px |

SP で 9,025px → 約6,200px。B と組み合わせても実装コストはほぼ増えない。

## 6. A（真のタブ）を選ぶ場合に必ず守ること

判断が変わった時のために、制約を残しておく。

1. **全パネルを DOM に残す。** 条件レンダリングではなく `hidden` 属性を使う（`PrefRegionPicker` と同じ）。
2. **`[hidden] { display: none }` を明示的に書く。** `.ad-metric-grid` などが `display: grid` を持つため、
   作者スタイルが UA の `[hidden]` に勝ってしまう。`globals.css` の `.home-region-panel[hidden]` に同じ落とし穴の前例がある。
3. **FAQ は初期表示タブに置くか、タブ化の対象外にする**（`lib/faq.ts` の可視性要件）。
4. `.ad-reveal` は `animation-fill-mode: both` の CSS アニメで、再表示時に再生されない＝ちらつきは起きない。
5. WAI-ARIA tabs パターン（`role="tablist"` / `aria-selected` / roving `tabIndex` / ←→Home End）を実装する。
   `PrefRegionPicker` がそのまま参考実装になる。
6. GA4 のスクロール深度・エンゲージメント指標が不連続になるので、切替日を記録しておく。

---

## 7. 推奨

**B（セクションナビ）を実装し、必要なら C（ランキングと回遊カードの折りたたみ）を足す。**

モックのタブバーの見た目と「長いページを渡り歩ける」価値を得つつ、
このページが担っている SEO 上の役割（可視な FAQ・61〜77本の内部リンク）を一切損なわない。
A は初期表示の高さでは最も効くが、失うものが集客の中核に直結するため、
本当に必要だと分かってから（例: GA4 でスクロール到達率が著しく低いことが確認できてから）で遅くない。
