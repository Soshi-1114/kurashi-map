# KurashiMap デザイン刷新 実装計画

作成日: 2026-10-06
状態: 段階実装中。第一段階はPR作成済み、公開前。

実装トラッキング: 2026-10-06 第一段階（共通文字組み、ランキング・詳細・比較画面）をPR化。比較候補の保存、トップ、地図は後続PR。

## 1. 目的と完成像

コンセプトは「暮らす街を選ぶための地図帳」。街を見つける、データを読む、候補を比較する流れを共通のデザインでつなぐ。

最初の成果物は、モバイルの「ランキング → 自治体詳細 → 2自治体比較」の3画面。ここで文字組み・情報階層・操作の一貫性を確認し、トップと地図へ展開する。

完成条件:

- ランキングと詳細から、迷わず比較を開始できる。
- 指標の数値・単位・比較基準・基準時点・出典を読み分けられる。
- 最大3自治体の候補をページ移動後も扱える。
- トップで街名検索と地図探索を選べる。
- モバイルの地図・凡例・ボトムシート・比較操作が重ならない。

## 2. 現状と前提

ローカルコードと設計資料を確認した。実画面、最新のGA4/GSC値、本番への反映状況は準備段階で確認する。過去の資料中の流入比率を現在の実測値として扱わない。

- `app/globals.css` に色・余白・文字・角丸の共通トークンがある。新しい並行テーマは作らず拡張する。
- 詳細には特徴の要約、平均比較、`SectionNav`、出典表示がある。再利用して配置と強弱を整える。
- 比較はPCの表とモバイルの指標別リストが実装済み。最大件数は `lib/siteNav.ts` の `MAX_COMPARE = 3`。
- `compare_ready` は2件以上のデータ取得後、`compare_view` は完成した比較表の先頭の視認後に発火する。この意味を維持する。
- 比較CTAの実験ID `compare-cta-placement-2026-10` とタイトル実験に関連するコードがある。公開状況・期間・終了条件を先に確認する。
- 作業ツリーにはランキングページ等の未コミット変更がある。実装開始時に再確認し、既存作業と差分を混ぜない。
- `deploy-preview.yml` は手動のプレビューデプロイ専用。本番公開の手順は別途確認する。

関連資料: [トップ刷新](home-renewal-plan-2026-08.md)、[詳細ナビゲーション](area-page-navigation.md)、[計測](analytics.md)、[GA4カスタムディメンション](analytics-ga4-custom-dimensions.md)。

## 3. 共通設計

### 見た目

| 用途 | 方針 |
|---|---|
| 色 | 既存の白 `#FFFFFF`、背景 `#F7FAFC`、文字 `#1E293B`、青 `#3A739E`、淡青 `#EAF4FB`、補助文字 `#64748B` を利用 |
| 書体 | 日本語システムフォントを基本に既存スタックを調整。追加Webフォントは初期導入しない |
| 本文 | 読む領域を16px、補足を13〜14pxへ段階移行。地図操作と密な表は別用途として扱う |
| 数値 | 対応フォントでは等幅数字。表は数値右揃え、単位の位置を統一 |
| 見出し | 自治体名と主要数値を大きくし、補足・出典と明確に差をつける |
| 枠・影 | 関連するデータを枠でまとめる。影は浮動UIを中心に使用 |
| 操作 | 主操作は青塗り、補助操作は枠またはテキスト。状態を色だけで伝えない |

既存の `--text-base` を一括で変更すると地図や診断にも波及するため、読む領域用の用途トークンを追加してページ単位で適用する。採用値はPC・モバイルの3画面で決める。

### 実装上の契約

- `lib/types.ts`、データスキーマ、欠損判定ヘルパー、家賃の色しきい値は維持する。
- 欠損をゼロで補わない。「データなし／対象外／区別非公表／未収録」を既存ルールで表示する。
- 公的な将来人口推計は基準年と推計であることを明示する。定義・時点が異なる指標を機械的に差し引かない。
- トップは静的地図プレビュー、地図は軽量summaryと選択後の個別取得を維持する。
- 本文・一覧・回遊リンクはSSR/SSGを維持し、操作部分だけをClient Componentにする。
- 詳細の目次はアンカーリンク。本文をタブ内に移して非表示にしない。
- URL、canonical、構造化データと可視本文の対応を維持する。タイトル変更は既存実験の作業として分離する。
- 新しいデータ指標・ページ種別は本計画に含まない。

- セクションの配置変更に合わせてアンカー、sticky位置、現在地表示を更新する。

完了条件: 小画面でも街名・単位・出典が欠けない。欠損や非公表を読める。比較リンクと地図リンクが機能し、既存実験のイベント定義を維持する。

### PR3: 比較画面の刷新

対象: `components/compare/CompareClient.tsx`、`app/compare/compare.css`、`lib/compareMetrics.ts` の表示接続部分。

- PCは自治体名と指標名を追いやすい表にする。sticky要素はスクロール領域と組み合わせて検証する。
- モバイルは既存の指標単位の縦並びを維持し、自治体名・数値・平均の階層を強める。
- 0件は検索への案内、1件は2件目の追加案内、2〜3件は比較結果を明確にする。
- 取得中・一部取得失敗・再試行・削除を扱い、未取得をゼロとして描かない。
- 全国/県平均の既存条件、集計対象外の説明を維持する。
- DOMの変更に合わせて `compare_view` の観測対象を更新する。

完了条件: URL共有、直接アクセス、戻る/進むが機能する。2件以上の取得完了と実際の視認が別々に計測され、PC/SPの両DOMによる重複発火がない。

### PR4: ページをまたぐ比較候補リスト

新規候補: `lib/compareSelection.ts`、`components/compare/CompareSelectionProvider.tsx`、`CompareSelectionBar.tsx`、`CompareToggleButton.tsx`。既存の命名・構成に合わせて実装時に確定する。

接続先: ランキングの自治体行、自治体詳細、比較ページ。地図への接続はPR6。

- 最大3件、同一コード重複なし。自治体名と「外す」を表示する。
- 0件ではバーを非表示、1件では「もう1件選ぶ」で既存比較ページの検索へ案内、2〜3件では「N件を比較」を主操作にする。
- 上限時は勝手に入れ替えず、解除方法を案内する。更新は `aria-live` で通知する。
- 候補は自治体コードと必要最小限の表示情報のみ保持し、フルデータを保存しない。
- 同一タブ内の移動・再読み込みを対象に `sessionStorage` に保存する。保存不可時はメモリだけで動作する。
- SSRの初期状態は空。マウント後に復元し、復元前の空状態で保存内容を上書きしない。
- 比較ページでは明示的なURLの `codes` を優先し、保存候補を勝手に追加しない。明示的な空指定も扱う。URL未指定時だけ保存候補を利用する。
- 比較画面の追加/解除はURLと候補を同期し、戻る/進むでも一致させる。削除後に保存候補が復活しないようにする。
- 保存値とURLを検証し、不正・未知コード、重複、4件以上を正規化する。候補復元のために全Municipalityをロードしない。
- 一覧全体をクライアント化せず、共有ストアと小さい操作部品に限定する。ルートProviderを使う場合も本文はServer Componentのchildrenとして保つ。
- 下部バーの高さとsafe areaを本文余白へ反映し、リンクやフッターを覆わない。

計測:

- 追加/解除は新しいイベントとして記録し、既存の比較ページへ遷移するCTAクリックと区別する。
- 比較開始時の `tool_source` は実際に開始した画面とする。詳細・地図などの追加語彙は `lib/siteNav.ts` に集約する。
- 過去の実験属性を候補に保存して別画面へ持ち越さない。旧実験対象の操作変更は評価終了後に公開する。
- イベント仕様・必要なGA4ディメンションは `docs/analytics*.md` と同時更新する。

完了条件: 追加→別ページ→2件目追加→比較→解除→再読み込みが一貫する。ストレージ不可、上限、重複、直接URL、履歴移動のケースが成立する。

完了条件: 320px幅でも横にはみ出さず、検索候補とナビが衝突しない。比較バーの有無でも操作できる。タイトル実験の変更と分離できている。

- 複数災害レイヤー、避難場所、ズーム条件、対象外表示の現行仕様を維持する。

完了条件: 縦横画面、safe area、ソフトキーボード表示、3段階シートで操作が隠れない。指標切替、自治体選択、地図移動、候補追加が両立する。

## 6. 効果測定と公開

### 指標

- 主指標: 各入口を利用したセッションのうち、2件以上の `compare_view` まで到達したセッションの割合。
- 補助指標: 既存CTAのクリック/視認、候補2件到達/候補追加開始、`compare_view` / `compare_ready` のセッション到達率。
- トップ: 検索確定・地図遷移の利用率。地図: 自治体選択後の詳細/比較への遷移率。
- ガードレール: LCP/INP/CLS、取得失敗、検索流入ページのクリック・表示回数。

イベント件数の単純な割り算でセッション到達率を代用しない。現在のGA4設定で利用可能な分母・経路集計を準備段階で確認し、必要な計測を公開前に整える。新パラメータは過去へ遡って取得できない前提で開始日を記録する。

### 公開順と評価

1. 準備で実験の終了・継続条件を確認。既存実験の対象ページや比較画面に影響する刷新は評価区間に混ぜない。
2. PR1〜3で3画面の刷新をプレビュー確認し、既存実験の評価後に第一弾として公開する。
3. PR4の候補機能を第二弾、PR5のトップを第三弾、PR6の地図を第四弾として公開する。
4. 各公開のコミット、日時、対象ページ、計測仕様を記録する。同じ曜日構成で比較し、まず14日を観測目安とする。
5. 必要な標本数は準備段階の基準率と検出したい差から決める。流入が少ない場合は観測を延長し、14日経過だけで改善と判定しない。前後比較には流入構成などの影響が残ることを記録する。

共通CSSも既存実験へ影響するため、対象ページだけのCTA除外では十分ではない。実験継続中は新スタイルを本番対象へ適用せず、プレビューで開発を進める。

公開は既存の手動フローに合わせる。プレビュー専用Actionを本番用に読み替えない。本番公開手順を確認してから各段階を反映する。

### 差し戻し

- 各段階を独立してrevertできるPRにする。大きなCSS移設と機能変更を混ぜない。
- 比較不能、主要操作の不可視、データの誤表示、明確な性能退行が見つかったら対象段階を戻す。
- 候補保存キーにバージョンを持たせ、古い/壊れた値を安全に無視する。URLで直接比較する既存経路を維持する。
