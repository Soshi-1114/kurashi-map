# 地域雑学クイズ機能の設計検討（2026-09）

きっかけ: 「バスに使うお金が1番多い県は？→ 長崎県。なぜ？→ 平地が少なく坂が多いから」
のような**地域の雑学クイズ**を新コンテンツにしたい、という提案。

本文書はその深掘り（コンセプトと出題設計）。結論を先に置き、以降で根拠・設計・落とし穴・段階計画を述べる。

**続編**: 流入とマネタイズの検討は
[`quiz-feature-growth-and-monetization-2026-09.md`](./quiz-feature-growth-and-monetization-2026-09.md) にある。
同文書で §11 の実装計画（PR-1〜5）は **MVP 1本に圧縮**され、撤退基準が追加されている。
着手前にそちらを読むこと。

---

## 1. 結論（先出し）

1. **クイズ自体はやる価値がある。** ただし「答え」は `data/*.json` から**ビルド時に計算**し、
   ハードコードしない。KurashiMap には既に 35 ランキング定義（`lib/rankings.ts`）と
   県別集計（`lib/prefAggregates.ts` / `lib/prefRanks.ts`）があり、**新データ 0 件で数千問**
   出題できる。新規データ取得は v1 では不要。
2. **例に挙がった「バス代」型はそのままでは実装できない。** 出典が家計調査（総務省）で、
   本サイトは収録していない。さらに家計調査の品目別ランキングは**県庁所在市のみ**で、
   1,918 自治体という本サイトの粒度と噛み合わない（§10 で採否を検討）。
3. **最大の論点は「なぜ？」の扱い。** 「坂が多いから」は**データではなく解釈**であり、
   サイトの唯一の差別化である honesty 方針（推計・プレースホルダを一切置かない）と
   正面衝突する。無出典の因果説明を LLM で量産した瞬間、本サイトの信頼性の土台が崩れる。
4. **その解決として「統計リテラシー型クイズ」を提案する（§4）。** 実データを探索したところ、
   本当に面白い問題ほど「なぜ」が**因果の推測ではなく統計の定義そのもの**で説明できる
   ことが分かった（例: 空き家率日本一は軽井沢町 70.4%。理由は別荘＝二次的住宅が
   「空き家」に含まれるため）。これは出典に基づく説明であり、honesty 方針と矛盾しない
   どころか、**サイトの主張を補強する**コンテンツになる。
5. **URL は増やさない。** 47県×指標で自動生成した大量のクイズ URL は、Google の
   ロングテール薄ページ／ドアウェイ判定の直撃コース。`/shindan`・`/compare` と同じく
   **少数の静的ページ＋クエリパラメータで状態を持つ**方式にする（§8）。

## 2. なぜこのサイトでクイズが効くのか（SEO/GA4 の文脈）

`docs/seo/` の分析には、この施策を支持する材料が既にある。

- **「意外な答え」はクリックされている実績がある。**
  `gsc-seo-implementation-plan-ctr-2026-08-28.md` に、`population-density-low`
  （日本一人口密度が低い＝歌志内市）が **CTR 6.5%（48click/743imp）** で好調、
  「答えが特殊で面白いページはクリックされている」と明記されている。
  一方で `population-most`（答えが横浜市＝退屈）は CTR 1% 前後。
  **雑学性そのものが CTR の要因**であるという自サイト内の傍証。
- **回遊の課題に直接効く。** 同文書では「ランキング流入が『読んで帰る』型に留まっており、
  `select_municipality` が 437→374 と微減」が課題として挙がっている。
  クイズは**滞在・回遊を作るフォーマット**そのものであり、解答後に
  `/area/{pref}/{code}` と `/ranking/{slug}` へ送客できる。
- **未インデックス自治体ページへの内部リンク供給になる。**
  municipality Exposure Rate は 45.46%（872/1,918）。クイズの答え・選択肢の
  すべてが自治体詳細への内部リンクになるため、**クロール導線が薄い自治体に
  リンクを配る仕組み**として機能する。ここは意図的に「答え以外の選択肢にも
  リンクを張る」設計にする価値がある。

つまりクイズは**新規キーワード獲得施策ではなく、エンゲージメント＋内部リンク施策**
として位置づけるのが妥当。新規流入を期待しすぎないこと（§9 の計測もその前提で置く）。

## 3. 実データ探索の結果（新データなしで何が出せるか）

`data/*.json`（1,747 の market-level 自治体）を実際に走査して確認した。以下はすべて
**現時点の収録データから計算した実値**であり、クイズの素材としての質を判断する材料になる。

| 問い | 答え | 値 | 面白さの理由 |
|---|---|---|---|
| 空き家率が日本一高い市区町村は？ | 長野県 **軽井沢町** | 70.4%（20,030戸/28,460戸） | 「空き家＝衰退」の直感を裏切る。別荘が空き家に計上される |
| 家賃平均が日本一安い市区町村は？ | 栃木県 **那須町** | 13,623円/月 | 観光地イメージとのギャップ。空き家率も61.7%で全国2位 |
| 高齢化率が日本一高い市区町村は？ | 群馬県 **南牧村** | 68.1% | 3人に2人が65歳以上という桁違いの値 |
| 人口密度が日本一低い市区町村は？ | 福島県 **檜枝岐村** | 1人/km² | 1km²に1人 |
| 面積が日本一広い市区町村は？ | 岐阜県 **高山市** | 2,177.61km² | 「市」が県より広い |
| 外国人住民の割合が日本一高いのは？ | 北海道 **赤井川村** | 53.3%（569人/1,067人） | 半数超。ニセコ圏のスキーリゾート（要注意 §7） |
| 鉄道駅が日本一多い市区町村は？ | **大阪市** | 288駅 | 東京23区が分割されている影響で大阪市が1位 |
| 家賃の県内中央値が全国5番目に高い県は？ | **沖縄県** | 54,150円/月 | 物価の直感を裏切る |
| 高齢化率の県内中央値が最も高い県は？ | **高知県** | 43.8% | 秋田43.7%とほぼ横並び（僅差＝出題には不向き §6） |

**重要な発見**: 上の表で面白い問題ほど、「なぜ？」が
**因果の推測ではなく「その統計が何を数えているか」の説明**になっている。

- 軽井沢の空き家率 → 住宅・土地統計調査の「空き家」には**二次的住宅（別荘等）が含まれる**
  （総務省統計局の用語定義）。
- 大阪市の駅数 → 東京23区は**特別区ごとに分割集計**されるため、単独自治体としては大阪市が上に来る。
- 那須町の家賃 → 別荘地の民営借家という**母数の小さい標本の加重平均**。

これは推測ではなく出典の定義・集計単位に書いてある事実なので、**出典を示して説明できる**。

## 4. 提案するコンセプト:「統計リテラシー型クイズ」

一般的な地域雑学クイズ（「◯◯県の名物は？」）とは別路線を取る。

> **直感 → 実データ → 「なぜそう見えるのか」の3段構え。**
> 驚きの源泉を「珍しい豆知識」ではなく「**直感と統計の定義とのズレ**」に置く。

このコンセプトの利点:

- **honesty 方針と矛盾しない。** 解説が出典の定義に基づくため、無出典の因果説明を書かずに済む。
- **サイトの主張を補強する。** 「空き家率が高い＝住みにくい、ではない」を体験的に伝えることは、
  地図やランキングを**誤読させない**ことにも直結する。クイズが利用者教育を兼ねる。
- **競合と差別化できる。** 一般的な雑学クイズサイトには政府統計の全自治体データがない。
- **ネタが枯れない。** 35ランキング × 47都道府県 × 複数の出題型で、常に新問を出せる。

一方で、**「面白さの担保は自動化できない」**ことは受け入れる必要がある（§6）。
候補の自動抽出はできるが、最終的な出題可否と解説文は人が判断する。

## 5. 出題アーキタイプ

`lib/rankings.ts` の `RankingDef`（`qualifies` / `sortValue` / `display` / `columnLabel`）
から機械的に導ける型を優先する。

| # | 型 | 例 | 生成元 | v1 |
|---|---|---|---|---|
| A | 全国1位当て（4択） | 「空き家率が全国で最も高い市区町村は？」 | `RANKINGS` の top1 | ✅ |
| B | 県内1位当て（4択） | 「群馬県で高齢化率が最も高い市町村は？」 | `prefRanks` | ✅ |
| C | 2択どっち？ | 「川口市と越谷市、家賃が高いのは？」 | 同県・同規模ペア | ✅ |
| D | 数値帯当て（4択） | 「軽井沢町の空き家率は？ ①20%台 ②40%台 ③50%台 ④70%台」 | `display` の値をビン化 | ✅ |
| E | 県ランキング当て | 「家賃の中央値が最も安い県は？」 | `prefAggregates` | v2 |
| F | 地図クリック型 | 選択肢を地図上のポリゴンで選ぶ | MapLibre + summary | v3 |
| G | 順位並べ替え | 3自治体を高齢化率順に並べる | 任意ランキング | v3 |

**A/B は「答えが小さな町村」になりがち**（軽井沢・那須・南牧村…）。これは
雑学としては良い（意外性が高い）が、**選択肢の作り方を誤ると当てずっぽうで当たる**
（4択のうち1つだけ聞いたことのない村名 → それが答え）。§6 のダミー選択肢ルールが必須。

C は「難易度を調整しやすく、地元の人が確実に楽しめる」ため、**回遊目的では最も費用対効果が高い**。

## 6. 出題品質のルール（ここが実装の本体）

### 6.1 ダミー選択肢（distractor）の生成則

1. **同じ母集団から採る。** 全国1位当てなら「同じ指標の上位20位以内」から選ぶ。
   知名度でバレる（有名市 vs 無名村）状態を作らない。
2. **僅差を混ぜない。** 正解と各ダミーの間に**最小ギャップ**を要求する
   （例: 相対差5%以上、または順位差3以上）。高知43.8% vs 秋田43.7% のような
   ペアは「実質どちらも正しい」ため出題禁止。
3. **同一データ源・同一時点に揃える。** 家賃（2023）と高齢化率（2026-01-01）を
   跨いだ選択肢は作らない。
4. **センチネルを除外する。** `hasRent` / `hasLandPrice` / `hasVacancy` /
   `hasForeignData` / `isWaitlistDisclosed` / `hasShelterData` / `isHazardEvaluated`
   等の既存ヘルパーを必ず通す。判定を再実装しない（CLAUDE.md の規約）。
5. **行政区を混ぜない。** `muniLevelOnly()` を通し、政令市と区の二重計上を避ける。

### 6.2 「面白さ」の候補スコア

自動で**出題候補**を並べるためのスコア（最終判断は人）。

```
surpriseScore =
    gap(1位と2位の相対差)          // 断トツなら盤石な問題になる
  × counterIntuitiveness            // 答えの人口規模が小さいほど高い／
                                    // 他指標の順位と乖離しているほど高い
  × recognizability                 // 答えの自治体の知名度（人口・駅数の代理変数）
```

`lib/highlights.ts` が既に「目立つ指標」を偏差と順位パーセンタイルでスコア化しており、
その思想をそのまま流用できる（`HIGHLIGHT_THRESHOLDS` と同じく定数を1箇所に置く）。

### 6.3 「なぜ？」の型で honesty を強制する

**設計上の要**: 型で「無出典の説明」を書けなくする。

```ts
// lib/quiz.ts
export type QuizExplanation =
  /** データの言い換えのみ。自動生成可。因果を述べない。 */
  | { kind: "data"; text: string }
  /** 統計の定義・集計単位に基づく説明。出典必須。人が書く。 */
  | { kind: "definition"; text: string; source: string; sourceUrl: string }
  /** 地理・産業等の外部要因に触れる説明。一次資料の出典必須。人が書く。 */
  | { kind: "cited"; text: string; source: string; sourceUrl: string };
```

- `kind: "data"` は「軽井沢町の空き家は20,030戸で、住宅総数28,460戸の70.4%です」のような
  **値の言い換えに限定**する（`lib/insights.ts` と同じ流儀）。
- 因果に踏み込む文（「別荘が多いから」）は `definition` か `cited` にしか書けず、
  `source` / `sourceUrl` が型で必須になる。
- **`kind` に無出典の自由記述を追加しない**ことを、この文書とコメントで明示的に固定する。
- 「坂が多いから」型の説明を将来どうしても書きたい場合は、`cited` に
  自治体公式資料・白書等の一次資料 URL を添える以外の道はない。書けないなら出題しない。

CI で `sourceUrl` の形式（https、ドメインの許可リスト）を検証する。

### 6.4 答えは絶対にハードコードしない

本リポジトリは GitHub Actions が**スケジュールでデータを更新して main にコミット**する
（`data-update-annual.yml` / `data-update-quarterly.yml`）。
「家賃が一番安いのは那須町」と静的に書いた瞬間、**次の住宅・土地統計調査で静かに嘘になる**。

したがって:

- 人が書くのは **`questionId` + 問題文テンプレート + 解説**のみ。
- **答えと選択肢はビルド時に `data/*.json` から計算**する（`lib/shindan.ts` と同じく
  サーバー側で前計算し、クライアントには軽量な `QuizQuestion[]` だけを配る）。
- **CI テストで「解説が前提としている事実」が今も成立するか検証する。**
  例: 軽井沢の解説は「1位である」ことを前提にするので、
  `expect(topOf("vacancy-high").code).toBe("20321")` を置く。
  データ更新で1位が変わったら**CI が落ちて気づける**。これが最重要のガードレール。

## 7. 落とし穴（実データで実際に踏んだもの）

### 7.1 分母のズレによる「見かけの外れ値」

赤井川村の外国人比率 **53.3%（569人/1,067人）**。ところが、

- 分子 = 在留外国人統計（2025-12・住民基本台帳ベース）
- 分母 = `population`（2025年国勢調査ベース）

スキーリゾートの季節労働者を多く抱える村では、この2つの基準のズレが比率を大きく動かす。
**サイトの地図・ランキングでは「同じ計算式の中の1点」として中立に扱えるが、
クイズとして「日本一」と断言すると、統計の性質を誤って伝えるリスクが上がる。**

対策: `foreign-ratio-high` のような**分母が別出典の指標は、比率型クイズの出題対象から
既定で外す**か、出題するなら解説（`definition`）で基準の違いに必ず触れる。
`lib/types.ts` は既に「派生値は保存せず実行時算出」と明記しており、
その注意書きをクイズ側にも引き継ぐ。

### 7.2 小標本の外れ値

那須町の家賃 13,623円/月 は、別荘地の民営借家という**標本の小ささ**を反映している可能性が高い。
値そのものは公表値なので収録に問題はないが、「日本一家賃が安い街」として提示すると
「移住したら1.3万円で借りられる」という誤解を生む。

対策: 家賃・地価など標本依存の強い指標は、**D（数値帯当て）や C（2択）を優先し、
A（全国1位当て）では解説で必ず母集団に触れる**。

### 7.3 集計単位の非対称性

- 東京23区は特別区ごと、政令市は市単位（`level: "ward"` は `muniLevelOnly` で除外）。
  この非対称性が「駅数1位=大阪市」を生んでいる。**問題文で単位を明示**する
  （「市区町村単位で」「政令市は市全体として」など）。
- 待機児童（政令市は市単位・区別非公表あり）、財政力指数（23区は都区財政調整制度下で
  ランキング対象外）など、既存の除外規則を必ず尊重する。

### 7.4 コンテンツの方向性リスク

- **治安・犯罪データは扱わない**（法務方針）。クイズは「意外な数字」を求める性質上、
  「危ない街」系に引きずられやすい。**方針として明文化**し、テストでも指標の
  許可リストを固定する。
- 「住みたくない街」「最下位はどこ」型の煽り文言は、指標の向き（`order`）を
  そのまま使うだけで自然発生してしまう。`lib/prefAggregates.ts` が
  「高い＝良いという含意を持たせない」と明記している姿勢を、問題文・解説にも適用する。

### 7.5 ペイロード

2段階配信が本サイトの中心的な設計。クイズはこれを壊しやすい（全自治体を配って
クライアントで問題を作りたくなる）。**必ずビルド時に問題を確定**し、1問あたり
数百バイトの `QuizQuestion` だけを配る。フル `Municipality` は解答後の遷移先
（`/area/...` または `/api/muni/[code]`）に任せる。

## 8. ページ・URL 設計

`/shindan`・`/compare` と同じ「**骨格は SSG の静的 HTML、状態はクエリ**」方式に揃える。

```
/quiz                     クイズのトップ（説明・テーマ選択・FAQ・構造化データ）
/quiz?t=vacancy&q=3       出題状態（クエリで持つ。個別URLを増やさない）
/quiz/{theme}             テーマ別ハブ。8〜12本に限定して手で作る
                          例: /quiz/akiya（空き家）, /quiz/jinko（人口）,
                              /quiz/yachin（家賃）, /quiz/saigai（防災）
```

**やらないこと**: `/quiz/{pref}` を47本、`/quiz/{metric}/{pref}` を数百本の自動生成。
本サイトは既に ranking 系で県別ページを大量に持っており、そこに実質同内容の
クイズページを重ねると、`docs/seo/` が繰り返し問題視している「薄いロングテール」
「クロール済み-インデックス未登録」を自ら増やすことになる。
**テーマ別ハブは、その回に出題する問題と解説を可視テキストとして持つ**ことで
（クイズを解かなくても読める記事として成立させる）、初めてインデックス価値を持つ。

構造化データ: `/quiz` は `WebApplication`（`/shindan` と同じ）、
テーマ別ハブは **`Quiz` / `FAQPage`** を検討。ただし Google の
リッチリザルト対象は限定的なので、**期待はせず正しさ優先**で入れる。

UI:
- モバイル優先。1問1画面、選択肢は縦積みの大きなタップ領域。
- 解答後に「答え・実数値・出典・解説」＋**その自治体の詳細ページへのリンク**。
  ここが回遊の本体なので、リンクは目立たせる。
- 全問終了後にスコアと**共有ボタン**（`components/ShareButton.tsx` を再利用）。
  OG 画像は `app/api/og/` の既存インフラで `/api/og/quiz/{theme}` を追加できる。

## 9. 計測（GA4）

`lib/analytics.ts` に既存の命名規則（`trackShindanRun` 等）に合わせて追加する。

```ts
trackQuizStart({ theme, questionCount })
trackQuizAnswer({ theme, questionId, correct, position })
trackQuizComplete({ theme, score, questionCount })
trackQuizResultClick({ municipalityCode, questionId })  // 回遊の本命指標
```

**成功の判定は「クイズの閲覧数」ではなく回遊**で見る:

- 主指標: `quiz_result_click` → `select_municipality` の増加、セッションあたり閲覧ページ数。
- 副指標: `quiz_complete / quiz_start`（完走率。低ければ問題数を減らす）。
- 問題ごとの正答率を `trackQuizAnswer` から取り、**正答率が 90% 超（簡単すぎ）や
  25% 近辺（当てずっぽうと同じ＝ダミーが機能していない）の問題を差し替える**。
  これが §6.2 の「面白さは自動化できない」への実用的な答えになる。

## 10. 例に挙がった「バス代」型をやる場合（家計調査）

結論: **v1 ではやらない。v3 以降の独立した判断とする。**

- 出典は総務省「家計調査」の品目別 都道府県庁所在市及び政令指定都市ランキング（e-Stat）。
  `scripts/_lib/estat.mjs` があるため**取得自体は既存の仕組みに乗る**。
- 障害は粒度: **県庁所在市＋政令市（約52市）しかない**。本サイトの
  「全47都道府県・1,918自治体」というデータモデルと合わず、`Municipality` に
  持たせると 1,866 自治体が欠損になる。持たせるなら**別ファイル・別型**
  （`data/kakei.json` + `lib/kakei.ts`）にし、クイズ専用データとして分離する。
- 領域も少しズレる。本サイトは「住みやすさ（住居費・人口・子育て・災害・インフラ）」で、
  家計調査の品目別支出は「生活実態・食文化」寄り。**サイトの一貫性を薄めるコスト**がある。
  一方、生活コストという意味では家賃・電気料金（`/denki`）と地続きでもあるので、
  **やるなら「支出」というテーマを明示的に追加する**という判断になる。
- そして肝心の「坂が多いから」は、**家計調査データを取っても出てこない**。
  §6.3 の `cited` として一次資料（長崎市の交通政策資料等）を探すか、書かないかの二択。

**より安く同じ面白さを得る代替案**: 面積調 CSV には**県計の行が既に含まれている**
（`scripts/fetch-area.mjs` のコメントに明記）。数行の追加で県面積が手に入り、
「岐阜県高山市は大阪府より広い？」型の**比較クイズ**が作れる。
新規の出典追加なしで雑学性が一段上がるので、家計調査より先にこちらを検討したい。

## 12. やらないことの明文化
