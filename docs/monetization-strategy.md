# KurashiMap マネタイズ戦略

更新日: 2026-08-12

このドキュメントは KurashiMap の収益化方針と、画面単位の導線配置設計をまとめたもの。
実装時の技術規約は末尾の「実装規約」を参照。導線の URL 生成は `lib/monetization.ts` に一元化する。

---

## 1. 基本方針

**「広告 PV で稼ぐメディア」ではなく「住む場所を決める直前のユーザーを送客するサービス」に寄せる。**

KurashiMap の検索流入は「○○市 住みやすさ」「○○市 家賃」など居住地選びの意思決定クエリが中心。
狙うポジションは「SUUMO を見る前に使うサイト」＝どの街に住むかを決める段階を取り、
決めた後のアクション（賃貸・引越し・回線など）を外部サービスへ成果報酬で送客する。

指標は `PV × 広告単価` ではなく `居住意思決定ユーザー × 送客単価`。

### 絶対に守ること（信頼性の防衛線）

- **ランキング・スコア・データ表示は売らない。** スポンサーによる順位優遇・表示優遇は全フェーズで禁止。
  売ってよいのは明確に分離・明示された PR 枠と送客導線のみ。
- データ可視化エリアと収益導線は視覚的に分離する（既存の `ad-support-section` と同じ考え方）。
- アフィリエイトリンクには **「PR」表記を必ず付ける**（景表法ステマ規制、2023-10〜）。
- ふるさと納税はポイント・還元訴求をしない（2025-10〜 制度上禁止）。
- CLAUDE.md の honesty 方針（推計値なし・治安データなし）は収益導線にも適用する。

## 2. 現状（2026-08 時点）

- 検索流入: 直近28日で Clicks 814 / Impressions 23,900（成長局面、Phase 1 相当）
- ASP: **アクセストレードに登録済み**（案件提携はこれから）
- ふるさと納税: さとふる審査落ち・ふるなび審査停滞のため**保留**。
  `FurusatoLink` / `generateFurusatoUrl` は env 未設定で非表示のまま休眠させる（削除しない）。
  将来、別 ASP 経由でふるさと納税案件と提携できたら env 設定だけで復活可能。
- 支援導線: `SupportBanner` 実装済み（`NEXT_PUBLIC_SUPPORT_URL` 未設定なら非表示）
- **未対応**: サイトに運営者情報・お問い合わせ手段がない。ASP の案件提携審査で
  不利になるため、`/about` に運営者情報＋連絡手段（メール or フォーム）を追加すること。

## 3. フェーズ計画

### Phase 1: 現在〜月1万PV — SEO優先＋最小限のアフィリエイトCTA

1. `/about` に運営者情報・問い合わせ導線を追加（提携審査の前提条件）
2. アクセストレードで提携申請: 賃貸ポータル系・引越し見積もり系・インターネット回線系
   （案件ラインナップと単価は管理画面で要確認。不足カテゴリは A8.net 等の併用を検討）
3. 自治体詳細ページ下部に「次のアクション」セクションを1つだけ設置（配置設計は §4）。
   広告だらけにしない。データエリアには置かない。
4. `track()` でクリック計測し、どの自治体・どの流入クエリが送客につながるか観測する

### Phase 2: 1万〜10万PV — 導線強化と計測

- 家賃カード・地価カードへの文脈インラインリンク追加（賃貸／土地・注文住宅・不動産査定）
- `/compare`・`/ranking` ページへの CTA 展開
- 「条件から街を探す」機能（住む場所診断）の検討 — 収益導線であると同時に指名利用を作る
  プロダクト機能。既存データ資産（家賃・地価・待機児童・災害・人口）をそのまま検索条件化できる
- 計測結果から高 CV 面に集中する

### Phase 3: 10万PV〜 — 高単価モデルへ展開

- 自治体 PR 枠（移住促進タイアップ）: `Sponsored` 明示の分離枠のみ。データ表示とは完全分離
- 住宅会社・不動産会社へのリード販売: フォーム＝個人情報の取得になるため、
  プライバシーポリシー改定と保管・受け渡しの設計が必要。ソロ運営での営業コストも重いため
  実需（問い合わせ）が観測されてから
- B2B データ提供（API/CSV/ダッシュボード）: 営業・契約・保守コストが高く後回し。
  なお元データは政府統計のため、売り物は生データではなく「統合・整形・継続更新」の部分
- AdSense 等ディスプレイ広告は補助収益。導入するならファーストビュー外・詳細ページ限定で、
  体験悪化と天秤にかけて判断

## 4. 画面単位の配置設計

### 4.1 自治体詳細ページ `/area/[pref]/[city]`（主戦場）

現在のセクション順: ヘッダー＋スコア → SectionNav → 特徴 → AI総評 → データで見る →
KPIカード → 詳細データ → 家賃が近い自治体 → 似ているエリア → 行政区 → ランキング →
FAQ → 出典 → 支援/ふるさと納税 → ページ下部CTA → フットナビ。

**P1（Phase 1・最優先）: 「{市名}に住むことを検討していますか？」セクション**

- 位置: 出典の後、既存の `ad-support-section` と同じゾーン（データエリアから分離した最下部）。
  既存の支援・ふるさと納税と統合して1つの「次のアクション」ゾーンにする
- 内容: 最大3ボタン（例: 「{市名}の賃貸物件を探す」「引越し料金を比較する」「ネット回線を探す」）
- 各ボタンは案件ごとの env（未設定なら非表示）＋「PR」ラベル＋外部サイト遷移の注記
- SectionNav に載せない（データセクションと同格に見せない）

**P2（Phase 2）: 家賃カード内の文脈インラインリンク**

- 位置: 詳細データ内「家賃・住居コスト」MetricCard の CompareBar 直下
- 内容: テキストリンク1本「{市名}の賃貸物件を見る [PR]」。データの隣に置く唯一の例外なので
  バナー化せず控えめに。`hasRent` が false（グレー自治体）でも表示可（物件は存在しうる）

**P3（Phase 2）: 地価カード → 土地・注文住宅・不動産査定**

- 位置: 「地価」MetricCard 直下。単価が高い商材（査定・注文住宅資料請求）と文脈が合う
- `hasLandPrice` が false の自治体では非表示

### 4.2 比較ページ `/compare`（Phase 2）

- 比較テーブルの下に「比較した自治体の物件を見る」CTA（自治体ごとのリンクを並べる）。
  比較まで進んだユーザーは意思決定の最終段階で、CV 期待値が最も高い面

### 4.3 ランキングページ `/ranking/[metric]`（Phase 2）

- `rent-cheap` / `rent-high` 等の家賃系ランキング下部にのみ賃貸・引越し CTA。
  検索意図（「家賃 安い ○○」）と一致する面に限定する

### 4.4 置かない面

- **トップの地図**（`/`、`/map/*`）: サイトの顔・信頼の源泉。収益導線は置かない
- KPI カード・スコアパネル・ハザード等のデータ表示内部（P2/P3 の指定位置を除く）
- 災害リスクセクション: 不安を煽って送客する形になるため、災害データの近くに商材リンクを置かない

## 5. 実装規約

- URL 生成・表示可否はすべて `lib/monetization.ts` に集約。実 URL・アフィリエイト ID は
  コードに直書きせず `NEXT_PUBLIC_*` env で管理（未設定 = 導線非表示）。ASP 乗り換えは env 差し替えのみ
- コンポーネントは `FurusatoLink` と同型パターン: `"use client"`、`track()` でクリック計測、
  `rel="noopener noreferrer"`、外部遷移の注記、「PR」ラベル
- 計測イベントは `affiliate_click` に統一し、`placement`（p1_next_action / p2_rent_inline など）・
  `program`（rental / moving / internet など）・`municipality_code` をプロパティで持たせる。
  面×商材×自治体で CV 分析できるようにする
- 秘密情報（ASP の API キー等）はクライアントに露出させない（既存方針どおり）

## 6. 見送り・保留の記録

| 施策 | 状態 | 理由 |
| --- | --- | --- |
| ふるさと納税アフィリエイト | 保留（コードは休眠） | さとふる審査落ち・ふるなび審査停滞（2026-08）。別ASP経由の案件が取れたら env 設定で復活 |
| AdSense | Phase 3 で再評価 | 現 PV では収益が小さく、地図 UI の体験悪化・中立的印象の毀損が上回る |
| ユーザー課金（プレミアム） | 見送り | 認証・課金基盤がなく（SSG構成）工数過大。有料ニーズの観測後に再検討 |
| B2B データ販売 | 見送り | 営業・保守コストがソロ運営と不整合。Phase 3 以降 |
| ランキング順位・データ表示の販売 | **恒久的に禁止** | サイトの信頼性＝競争優位を破壊するため |
