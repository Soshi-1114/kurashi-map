# GA4・GSCの手動評価ツール

本番の画面・イベント送信・GA4管理設定を変えず、同じ条件で取得・保存・再生成するためのツール。#241の観測中にも実行できる。#242のマージ・公開や評価の自動実行は行わない。

## 実行

Nodeはpackage.jsonのenginesに適合するバージョン（22.22.2以上の22系など）を使用する。

```sh
npm run analytics:report -- --end=2026-11-03 --days=28
npm run analytics:report
npm run analytics:report -- --input=reports/gsc/analytics/取得ディレクトリ/source.json
```

- `--end`: 指定終端。省略時はJSTの当日から3日前と、GSCの直近14日から確認できた最新確定日の早い方。指定日がその終端より後なら短縮して明記する。存在しない日付は拒否する。
- `--days`: 1〜90の整数、既定28。指定期間と直前同日数、7日・28日比較を出す。同じ取得条件は実行内で共有する。
- `--out`: 新規出力ディレクトリ。既存ディレクトリは上書きしない。既定は`reports/gsc/analytics/実行日時/`。
- `--input`: 保存データからAPI通信なしで再生成する。認証情報は不要。`--end/--days`との併用は拒否し、保存時の期間・条件を維持する。表示の形式は実行したコードの版による。

新しいAPI・依存関係・Secretは追加していない。ライブ取得は既存の`.env.local`を読み、`GSC_CLIENT_EMAIL`と`GSC_PRIVATE_KEY`、または`GOOGLE_APPLICATION_CREDENTIALS`を使う。同じサービスアカウントにGA4の閲覧権限も必要。スコープはGSC・GA4とも読み取り専用。別worktreeでは、Nodeの`--env-file=/元の作業場所/.env.local`で環境を読み込んでからCLIを実行できる。認証情報をコピー・コミットする必要はない。

## 出力と取得条件

- `source.json`: schemaVersion=1。取得時刻、プロパティ・ホスト・サイト、JST実行日、期間、確定日確認、GA4メタデータ、リクエスト条件とページごとの生レスポンス・状態。秘密鍵・トークン・Authorizationは含めない。
- `analysis.json`: 全体の集計、取得品質、比較導線のイベント・送り元・端末、ページ群のPV、固定評価の結果。
- `summary.md`: 人が読む集計表と制約。

GA4はproperties/542476262、`hostName=kurashimap.jp`完全一致。GSCはsc-domain:kurashimap.jp、Web、dataState=final。GA4はAsia/Tokyo、GSCはAmerica/Los_Angelesで、同じ日付でも同じ時刻範囲ではない。

GA4は100,000行、GSCは25,000行ずつページングし、各10ページで打ち切る。打ち切り・途中失敗は完全取得として扱わない。接続失敗・429・5xxは最大3回試す。失敗した集計は0件に変換しない。

終了コードは0=全取得完了かつAPI品質通知なし、1=認証・期間決定・引数・ファイル等の実行失敗、2=保存完了したが取得失敗・定義不足・打ち切り・品質通知あり。2の場合も取得済みデータは残す。認証エラーでは機密を含み得るSDKエラー全文を表示しない。

カスタム定義は登録前へ遡及しないため、過去の(not set)を不利用と断定しない。

閾値・サンプリング・(other)集約、想定外のGA4タイムゾーンは警告として残す。成功時の通知なしも、収集漏れや匿名化がないことを保証しない。

## 固定評価：電気・備蓄（#241）

- 公開当日10/31を除き、11/1〜11/14を観測。11/17以降かつ終端11/14まで取得できた時点で14日分が揃う。それ以前は中間集計。
- 新版はmeasurement_version=2026-10-31と、電気inline-v1／備蓄water-inline-v1が同じ行で一致するものだけ。入口視認回数・期間の総ユーザー数、入力・結果描画の総ユーザー数を集計する。
- 結果ユーザー／視認ユーザーは期間比率。日別ユーザー数を足さず、順序付きファネルとは呼ばない。結果イベントは描画であって結果そのものの視認・滞在ではない。
- 初期目標は結果表示率5%以上かつ各10人以上。入口500視認未満なら28日まで保留する。11/15以降のデータがあれば、11/1〜最長11/28を別表で追加し、14日評価の表を維持する。28日評価の反映待ち目安は12/1。28日でも母数不足なら判断保留を続ける。
- 基準10/17〜10/30は交通量の参考比較。旧版の視認定義変更をまたぐので新版と同条件のCTR比較をしない。10/25〜10/30を補助期間として保存する。旧版に存在しない結果描画イベントの増加率は計算しない。
- 詳細着地、試算、プラン視認、備蓄リスト表示・コピー・印刷要求も別表で確認。操作はcta_variantのないものもあるため、詳細操作と新版入口の厳密な接続は保証しない。
- 運営者の本番確認は識別できていない。目標到達の表示だけで成功・#242公開可否を決めず、品質情報と運営確認の影響を人が確認する。

## 比較導線の読み方

比較表の取得完了・視認、候補追加・開始を、全体・端末・tool_source別で出す。送り元URLが記録されていない場合は分類に留める。pagePathはイベント発生ページであり、比較表のpagePathから送り元を推定しない。

人口増加率の大阪・福岡に限定したcompare_ctaイベントはページ・端末別の別表とする。pref_ranking_top3は他の県別ランキングにも使われるため、同じ分類の比較表視認を対象2ページの成果と決めつけない。

ユーザー数は送り元・端末・イベント間で合算しない。ページ群のPVとGSCクリックはそれぞれ別の集計であり、比較利用との比率を厳密な転換率にしない。比較成立・視認の導入前（10/09以前）の0件や、定義変更をまたぐ数値で改善率を判定しない。
