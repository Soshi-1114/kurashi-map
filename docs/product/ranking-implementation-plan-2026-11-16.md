# ランキング起点の利用価値・収益改善 実装計画

作成: 2026-11-16。実装PRで管理する。マージ・本番公開・広告設定変更・外部ストレージ作成は今回の対象外。

## 目標と確認済みの需要

「短時間で数字を確認し、関心のある地域内で比較し、違いと追加確認事項が分かる」体験を優先する。指標数やPVだけで成功を判定しない。

11/16取得のGSC確定データ、10/17〜11/13対9/19〜10/16の28日比較では、駅数30→119、保育園・幼稚園数50→53、医療機関数18→35クリック。全国＋県別のページ群合計であり、施策の因果効果や全県への拡張根拠ではない。面積ランキングに合う返却語は4件5表示0クリック。学校数・年少人口割合等は一致する需要を今回確認できていない。詳細は[需要調査とコンパクト化案](ranking-compact-and-expansion-2026-11-16.md)。

## 今回の実装

1. **順位をすぐ読める画面:** 全国版の上位10件の重複を除き、先頭10件と続きを一つの順位付けで表示。スマホも順位・自治体・数値が読める行を基本とし、検索で下位も探せるようにする。既存タイトル・canonical・順位計算・欠損判定を保つ。
2. **地域選択:** 全国・既存の9地方区分・都道府県を選ぶ。関東は1都6県。全国上位100件の抜粋からではなく、対象地域の全有効自治体から順位を求める。地方はクエリで共有する閲覧状態とし、独立した検索用URLを一括生成しない。指標選択でも範囲を保持する。
3. **有用性アンケート:** ランキングと自治体詳細に「知りたかったことが分かったか」。肯定／否定と否定時の任意理由。ページ・項目・版ごとに保存し、回答件数と内訳を表示。自由記述、街の口コミ点数、住みやすさ順位への流用はしない。
4. **比較の要約:** 既存比較の先頭に、人口・人口増減率・家賃等の主要な違いを最大3点表示。計算可能な実数に限定し、基準時点の違いと判断できないことを示す。比較操作ページへの新規広告配信は行わない。
5. **診断の期待との整合:** 駅数は通勤時間、待機児童数は入園可能性を表さない。設問・説明を収録指標の意味へ合わせる。スコア計算は変更せず、既存実験と区別する。
6. **広告配置:** ランキングの既存1枠を、スマホでは先頭10件後、広いPCでは表の横へ配置する。広告より先に順位の答えが見える構成。単一の広告要素をCSSで配置し、端末ごとに二重リクエストしない。広告無効時に空のサイド欄を残さない。現行の公開フラグと枠IDを使い、新規枠や実配信の有効化はしない。

## デザイン

frontend-designスキルを適用。既存のBlue + Neutralを継承する。主要色#3a739e、ホバー#2e6a92、背景#f7fafc、白#ffffff、本文#1e293b、補助文#64748b。既存Inter／日本語サンセリフを使い、自治体名は左、数値は右揃え。順位は装飾カードから読みやすい表へ統一し、先頭3件の強調を控えめにする。44px程度の操作領域、キーボードフォーカス、320px幅、長い自治体名に対応する。

配置は「短い説明→対象地域・指標・自治体検索→先頭10件→広告（PCは表の横）→続き→有用性アンケート→解説」。統計の意味に関わる注記は折り畳みの中へ隠さない。一般的なダッシュボードの大きなサマリーカードは増やさず、順位を読むことに面積を使う。

## アンケートの保存と運用

静的JSONやGA4だけでは公開件数を安定して共有できないため、サーバーAPIと永続ストレージを分ける。Redis REST互換の保存先を環境変数で指定する方式とし、外部サービス契約・作成は自動で行わない。未設定・無効時はアンケートを表示せず、保存成功を装わない。

POSTは同一Origin、検証済みのページ・項目・版、署名トークン、匿名のHttpOnly Cookieを確認する。保存は原子的に行い、同じブラウザーの再回答と短時間の連投を抑える。Cookie削除や別端末をまたいだ一人一票は保証せず、「人」でなく「件」と表示する。自由入力・座標・生IPを保存しない。失敗時は再試行可能にし、成功した票だけを公開件数へ反映する。

環境設定、プライバシー説明、運用・停止方法と受入テストを同PRに含める。保存先未設定のまま本番のアンケート受入完了とは扱わない。

- 14日で受信・操作・流入構成、28日で有用性回答・比較/詳細到達・収益/セッションを評価。アンケートの回答率と件数、否定理由を併記する。広告収益はAdSense、成果報酬はASPの確定実績を正とする。
- 1回で答えが分かった訪問を失敗にしない。滞在時間やPVだけを増やす設計はしない。

## 検証

地域ごとの完全な母集団からの順位、対象外・0件・一覧型、クエリ復元、下位検索、比較・共有リンクをテストする。アンケートは入力検証・署名・同一Origin・同時重複・連投・保存障害・未設定の動作を確認する。比較要約は欠損と年度差を確認。typecheck、lint、テスト、データ検証、本番ビルドを行い、利用可能な環境でスマホ／PCの表示を検証する。実ブラウザーが使えない場合は操作確認の限界をPRへ記録する。
