# 利用者視点での再評価と、第一想起を取るための方針

作成: 2026-11-16。前回の[機能案](feature-ideas-research-2026-11-16.md)を利用者の課題から再評価したもの。実ユーザーへのインタビュー・利用テストの結果ではなく、公開ページ、コード、既存のアクセス分析に基づく仮説。

操作用ブラウザーを利用できず、実機でのタップ・スクロール・表示速度の検証はしていない。検索取得の公開ページにはキャッシュとローカル実装の差があるため、公開時点の細部の不具合は断定しない。コード・設定・公開状態は変更していない。

## 前の提案を修正する

前回は「既存のランキングから接続しやすい」という事業側の都合を重視しすぎた。現在地・順位検索は便利だが、それ自体で使い続ける理由にはなりにくい。独自記事も、見慣れた表の解説を増やすだけでは読む理由が弱い。

また、自治体詳細には既に「家賃水準が近い自治体」「家賃・人口規模が近いエリア」と比較へのリンクがある。同規模比較は、新しい紹介欄を追加する案から、既存候補を比べた後に違いが分かるようにする案へ修正する。

## 誰の、何のためのサービスか

| 利用者の状態 | その人が知りたいこと | 適した体験 |
|---|---|---|
| 人口等を検索してきた | 何位か、どれくらいの数か、以前と比べてどうか | すぐ答えが出る表、差・変化・基準日の説明 |
| 地元や気になる街を調べる | 自分が知る街と何が違うか、その背景は何か | 身近な街との比較、変化の図解、根拠のある解説 |
| 転居候補を探す | 通える範囲で、予算や生活条件に合う街はどこか | 必須条件による候補絞り込み、具体的な生活情報 |
| 候補を2〜3か所に絞った | 何を諦め、何を得るか、何を追加で確認すべきか | 差分と注意点の説明、街の中での違い、現地確認事項 |

アクセス上最も確認できているのは最初の状態。後の状態は価値が大きそうでも、現在の訪問者全員に当てはめない。PVを増やすために、短時間で解決する利用を無理に長引かせない。

## 提案機能を本当に使うか

| 案 | 利用者としての評価 | 使いたい状態にする条件 |
|---|---|---|
| 現在地ボタン | 地元の地図なら使う。転居先探しでは現在地が探索の起点とは限らない | 地図の補助操作として提供。看板機能にしない |
| 自分の街の順位検索 | 長い県別表なら便利。ただし知りたい街の順位は一度分かれば終わる | 表内検索・ジャンプとして軽く提供。指標をまたいだ変化や差に接続 |
| 同規模の街の紹介 | 人口が近いだけでは、比較する動機は弱い | 「今の街と候補の違い」「近隣で選ぶなら」という目的を先に置く |
| ランキング解説記事 | 一般論や表の読み上げなら読まない | 自分にも関係する疑問、意外性のある検証、一次資料、図解が必要 |
| 自由な街口コミ | 量と質が揃えば参考になるが、少数の匿名評価では判断しにくい | 当面は条件・時期を明示した取材で、具体的な暮らしの事実を集める |
| ミニ調査 | サイトの成長のためだけなら回答する理由が弱い | 短く任意にし、調査目的を明示。回答しなくても機能を使える |

## 既存機能で先に改善したいこと

### 1. 診断が答える範囲と、質問が約束する範囲

[住む街診断](https://kurashimap.jp/shindan)では、通勤重視を自治体内の駅数、保育園の入りやすさを待機児童数で測っている。災害は自治体区域内の最大区分、生活インフラは施設の実数を使う。測り方の表示はあるが、利用者が質問から期待する意味と指標の意味は一致しない。

- 通勤: 目的地までの所要時間・乗換・運行本数が分からない。駅の多さを通勤しやすさと受け取らせない。
- 保育: 年齢、園、時期、選考条件で異なる入園可能性を、待機児童総数だけでは答えられない。
- 医療: 施設の総数だけでは、自分が必要とする診療科や通える範囲が分からない。
- 災害: 自治体にリスク区域があることと、候補の住宅の状況を分ける必要がある。

短期は質問・結果名をデータが説明できる範囲へ合わせ、「統計で街を絞り込む」体験として期待を調整する。説明を読まないと意味が変わる設問を増やさない。中期はユーザー需要を確かめて、目的駅、具体的な生活施設、細かな地域の確認へ進める。

「とても重視」という重みだけでは、「県外には住めない」等の必須条件を表せない。まず都道府県・候補エリアを絞れること、除外条件と好みの重みを分けることを検討する。予算条件は、現在の自治体家賃平均では希望間取りの募集家賃を保証できないため、データ追加を伴う別要件。

### 2. 比較表を読んだあと、違いを理解できるか

比較には既にグループ移動、平均切替、モバイル専用の表示がある。比較画面全体の作り直しが必要とはいえない。一方で、先頭で主要な違いを示す要約は現行コードに見当たらない。

改善候補は、利用者が重視する指標から「AはBより○○が大きい」「家賃の基準時点は共通」「保育の比較はこの情報だけでは決められない」を3点程度にまとめること。計算結果と解釈を区別し、根拠となる表へ戻れるようにする。

「全国平均より上」よりも、利用者の基準となる街との差が欲しい場面がある。住んでいる街を必須登録させず、比較の基準を1つ選べるとよい。

[比較ページ](https://kurashimap.jp/compare)の例は人口上位から作る都市ペア。仕組みの実演にはなるが、実際に比較する動機は弱い。既存の需要を確認し、「同じ生活圏の候補」など選ぶ理由が分かる組み合わせへ変える余地がある。

### 3. 自治体・駅・生活圏の粒度

トップ検索では駅名で探せるが、主動作はその駅のある自治体詳細へ移動する。地図への副動作も自治体を開くため、駅周辺の情報を期待した人とは粒度がずれる可能性がある。

当面は検索候補・遷移先で「○○駅がある△△市の統計」と明示。将来は、駅や選択地点の周辺施設、通勤先、地域内の違いを確認できる方向を調べる。市平均の家賃や自治体全体のハザードを、その地点の値として表示しない。

## 読みたい情報・使いたい体験

1. **街の変化が見える。** 現在の順位だけでなく、比較可能な過去の人口から増減の推移を知る。国勢調査と住民基本台帳を混ぜず、境界変更を処理し、実績と将来推計を分ける。履歴データの取得・検証が必要な新規要件。
2. **知っている街との違いが分かる。** 人口順位の隣同士ではなく、関心のある街を基準に差分を要約する。候補を選ぶ理由と、比較できない項目も分かる。
3. **同じ市内の違いを確認できる。** 駅周辺と離れた地域、施設の分布など、街全体の平均から一段具体化する。全国対応を一度に目指さず、データの揃う小範囲で確認する。
4. **数字の背景を理解できる。** 「人口が増えている街は家賃も高いのか」「待機児童ゼロは保育園に入りやすいという意味か」等、解く価値のある疑問を扱う。原因の断定には別の根拠が必要。
5. **実際の生活の選択が見える。** 地域・時期・世帯条件を明示した取材で、通勤・買物・車の利用など日常の行動を伝える。個別の体験と地域全体の代表性を区別する。

このうち、比較の差分要約は既存データを生かして小さく試せる。変化の分析はランキング利用と接続しやすい。細かな生活圏情報・通勤は住み替え需要への価値が大きそうだが、取得・更新コストも高い。

## 「業界No.1」をどう捉えるか

目指す仮説は「街選びで、候補の違いと確認すべき点が最もよく分かるサービス」。機能数、全国のページ数、総合住みやすさ点数の多さは目標にしない。

街の情報を地図に載せるだけなら、国交省の[不動産情報ライブラリ](https://www.reinfolib.mlit.go.jp/map/manual/)でも多様なデータを扱う。通勤検索も[LIFULL HOME'S](https://www.homes.co.jp/chintai/map/)等にある。これらの機能があるだけで優位にはならない。KurashiMapは、データの違いを読み解き、次に何を調べればよいかまで案内する使いやすさを仮説にする。

必要なものは次の5つ。

- **課題の選択:** まずランキング・地域データの理解で強くなり、その利用者の中にある街選び需要を確かめる。
- **信頼:** 設問・見出しとデータの意味を一致させ、出典・更新・欠損・対象範囲を管理する。表示する比較根拠を追えるようにする。
- **固有の蓄積:** 検証済みの過去比較、編集した問いと図表、条件付きの生活取材を積み重ねる。表の自動生成だけでは模倣されやすい。
- **使い終えた成果:** 「違いを説明できた」「追加確認する点が分かった」「候補を絞れた」を測る。短い利用でも目的達成なら成功。
- **採算:** 収益/セッションと更新・取材・取得コストを見る。広告を増やして理解や信頼が落ちれば事業の基盤を損なう。

No.1は将来の目標であって現状の認定ではない。対象分野・比較する競合・評価方法を先に定義する。検索流入シェア、同じ課題での比較利用テスト、目的達成の自己申告、再利用・共有、売上と費用を併せて評価する。検索順位やPVの単一指標で断定しない。

## 次に検証すること

最初の1〜2週間は、直近の実利用に近い人5〜8人程度で探索的な利用テストを行う。統計確認、地元への関心、転居検討を分ける。この人数で市場を代表する結論や割合は出さない。

「この機能が欲しいですか」よりも、次の課題を渡し、迷い・誤解・自力でできたことを観察する。

1. 気になる街の人口と変化を調べ、情報の基準時点を説明する。
2. 知っている街と候補の街を比較し、違いを3つ説明する。
3. 診断結果から候補を選び、選んだ根拠と、まだ分からないことを話す。

まず診断の期待とのずれを修正し、比較の差分要約と変化の図解をそれぞれ小さく試す。目的達成の改善を見てから生活圏情報へ投資する。現在地ボタンと表内検索は、その間に提供できる補助改善として扱う。

広告は既存の公開待ち施策と重複させず、読者が最初の答えを得た後の区切りで試す。目的達成・回遊・表示の安定性を伴わない増枠を成功としない。
