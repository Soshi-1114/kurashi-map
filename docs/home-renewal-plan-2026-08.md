# トップページ刷新計画: 地図をトップから外し、汎用 /map ページへ移設（2026-08）

背景（2026-08-28 の議論）: トップの全画面地図は操作性が悪く、GA4 でも地図操作
（select_municipality）はユーザー +76% の中で微減（437→374/28日）と、流入の主流
（ランキング閲覧）が地図体験に接続していない。トップから地図を外し、代わりに
**地図専用ページへのリンクをわかりやすく配置**する方向で合意。ディープリンクの
行き先は**汎用 /map の新設**で受ける（指標ハブへの振り分けはしない）。

先行して PR #167 で /map/hazard ハブと `initialOverlays` prop を実装済み。
本計画はその続きで、着手前にこの文書を見直すこと。

## 決定事項

1. トップ（/）から全画面地図を撤去し、ポータル（検索＋導線集約）にする。
2. 現在のトップ地図体験は **/map（汎用地図ページ）** として新設のURLに移設する。
3. 既存の「地図で見る」ディープリンク（`mapHrefForCode`/`mapHrefForPref` の
   既定 path `/`）は **/map へ変更**する。指標ハブ（/map/rent 等）は現状維持で並存。

## 実装ステップ（PR分割案）

### PR-1: /map 新設（地図の引っ越し・トップは未変更）

- `app/map/page.tsx` を新設。現在の `app/page.tsx` の地図部分
  （HomeShell + MapView + summary 配信 + リソースヒント + initial-view.svg）を移植。
  title は「住みやすさマップ｜家賃・地価・人口・災害リスクを地図で比較 - KurashiMap」系。
  canonical は /map。
- `lib/mapDeepLink.ts` の `mapHrefForCode` / `mapHrefForPref` の既定 path を
  `"/"` → `"/map"` に変更（全「地図で見る」導線が一斉に切り替わる。呼び出し側の変更不要）。
- MAP_HUBS とは別枠で sitemap / フッターに /map を追加
  （「地図から探す」の筆頭リンク。MAP_HUBS に入れるとランキング対応テストと
  siteNav の意味論が崩れるため別掲にする）。
- トップの HeroSearch の自治体確定時の遷移先を確認: 現在は同一ページの地図へ
  pendingFly。PR-1 時点ではトップに地図が残っているため変更なし。
- リダイレクト不要（/ は残る）。/map は新規URLなので IndexNow 送信。

### PR-2: トップのポータル化（地図撤去）

- `app/page.tsx` から HomeShell/MapView を外し、構成を:
  1. ヒーロー: キャッチコピー＋ HeroSearch（確定時は `/area/{pref}/{code}` の
     詳細ページへ直行 or `/map?code=` へ。**推奨: 詳細ページ直行**。検索意図は
     特定の街の情報であり、詳細ページの方が答えに近い。地図で見たい人には
     詳細ページの「地図で見る」導線がある）
  2. 地図セクション: /map と指標ハブ5+1件のカード（initial-view.svg を
     プレビュー画像として流用し「地図を開く」CTA。タップ領域を大きく）
  3. ランキング導線（既存 HomeLinks の流用）
  4. 人気の自治体・県別リンク（既存流用）
  5. /denki・/compare などツール導線
- LCP: 地図撤去でトップは軽量化する。initial-view.svg の preload は
  地図カードに転用 or 削除。tiles.openfreemap.org への preconnect は /map へ移動。
- title/description: 「地図で比較」の訴求は維持しつつ、ポータルであることが
  わかる文言に調整（大幅変更は避け、8月のtitle施策の計測と混ぜない）。
- OG 画像は現状維持で可。

### PR-3: 後始末・整合

- 全ページの「地図に戻る」文言の見直し（`/` 行きリンクは「トップへ」、
  地図に行くものは /map へ。ランキングページの rk-footnav、エリア詳細の
  ad-back、404 等を grep で棚卸し）。
- `docs/area-page-navigation.md` 等の記述更新。
- GA4: /map の閲覧と select_municipality の相関を見る（トップ撤去の影響測定）。
- url-sets.json に /map セット追加（新設URL のゼロベース成長）。

## リスクと対策

- **ブランド/SEO**: トップ title「住みやすさを地図で比較」は維持（ポータルでも
  嘘にならない）。トップの検索流入はブランド系が主でリスク小。/ の内部リンク
  構造は変えない（HomeLinks は残る）ため、クロール導線への影響は限定的。
- **UU比の大きい Direct/AI 流入**: トップ着地で地図を期待するユーザーには
  ファーストビューに地図カード（大きめ）を置いて1タップで /map へ。
- **既存ブックマーク/被リンク**: / は消えないため 404 リスクなし。
  `/?code=xxxx` の旧ディープリンクは PR-2 後は地図がなく死ぬ →
  `app/page.tsx` で searchParams.code があれば `/map?code=` へ redirect() する
  互換レイヤーを入れる（検索エンジンや他サイトに残った旧URL対策）。
- **効果測定**: select_municipality（/map 上での発火）、トップの直帰・遷移先、
  /map の滞在。刷新前後で GA4 比較。

## やらないこと

- 指標ハブの統廃合（現状の /map/* はそのまま）
- トップの title の大幅変更（8月 title 施策の計測期間中）
- MapView 自体の操作性改善（別テーマ。モバイルのボトムシート改善等は
  /map 移設後に計測してから判断）
