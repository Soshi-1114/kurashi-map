# 電気・備蓄の入口改善（第1段階）

電気は10/25〜29の入口387視認・1クリック、備蓄は235視認・0クリック。入口で目安を確認する価値を提供し、詳細への移動だけを成果にしない。

## UIと入力

- 電気：自治体概要直後で人数別の大手従量電灯の月額目安を表示。計算式・単価・人数別使用量・既定アンペアは既存と同一。境界自治体では供給エリアを選び直せる。全プランJSONはサーバーで参照し、入口クライアントには基準額だけを渡す。
- 備蓄：自治体の災害情報直後とハザードマップの既存入口で、人数・3/7日から水量と2Lボトル換算を表示。詳細ページの初回入力前に在宅備蓄・避難判断の対象外であることを表示。フッターにも入口を追加。
- 入力は30分限定のsessionStorageで同じタブの詳細へ一度だけ引き継ぐ。URLはcode/from/quick識別のみで、人数・日数は含めない。通常URLでは入力を取り込まない。壊れた入力・期限切れ・別自治体・別送客元は無視する。
- 保存済みの備蓄記録は優先して復元し、入口の条件へ変更するには明示操作が必要。変更時は状態を未確認へ戻して水の在庫を保持。永続保存は従来同様ユーザー操作時だけ行い、入口から開くだけでは書き込まない。

## 計測

新しい入口のmeasurement_versionは2026-10-31。cta_variantは電気inline-v1、備蓄water-inline-v1。既存のentry_viewは50%以上の視認、entry_clickは詳細への移動。

追加イベント：denki_quick_interact / stockpile_quick_interact（初回の選択操作）、denki_quick_result_view / stockpile_quick_result_view（初回の人数選択で結果を描画した時）。結果イベントは結果の50%視認や滞在時間を保証しない。入力を変更しても各イベントは同一マウント中1回。人数・日数・金額・在庫は追加イベントへ送らない。

備蓄の詳細操作も2026-10-31版。保存なしで入口条件を適用した時は入力開始としてstockpile_startを1回記録。電気の引き継ぎだけではdenki_simulateを発火させない。既存の電気詳細入力の計測仕様は維持する。

## 公開と評価

1. 第1段階だけを先に公開し、デプロイ日・コミット・受信確認を記録する。公開当日と運営者の確認操作を評価から除外する。
2. 公開後14日を同じ曜日の直前14日と比較。主指標は入口視認ユーザーに対する結果表示ユーザーの比率（期間集計であり厳密なセッションファネルではない）。次に詳細着地・備蓄リスト表示・電気プラン視認を見る。
3. 運用上の初期目標は結果表示率5%以上・各機能10人以上の利用。500視認未満なら結論を保留し28日まで確認。目標達成を統計的な因果効果の証明とは扱わない。
4. 第2段階の広告配置は別PR。第1段階の公開後14日の評価を記録するまでマージ・公開しない。ASPとGA4のクリック差の調査は今回対象外。自動監視・自動公開の設定は含めない。
