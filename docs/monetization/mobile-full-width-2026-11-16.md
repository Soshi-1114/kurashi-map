# モバイル全幅広告への対応

## 対象と実装

AdSense「モバイル デバイスに全幅サイズで広告を表示する」の最適化案に対応する。
対象は既存の `kurashimap-ranking-content`（3494524776）と `kurashimap-area-content`（1055888689）。

- 共通の `DisplayAd` に `data-ad-format="auto"` / `data-full-width-responsive="true"` を設定。
- 広告本体の固定幅・高さを外し、Googleのレスポンシブサイズ選択を許可。PCにも自動サイズ選択が適用される。
- 外枠を高さ250px固定から最小高さ250pxに変更。未配信時の予約領域を維持し、大きい広告が入れば親要素も伸びる。
- 枠数・配置・配信対象・本番限定の配信条件・二重初期化防止は維持する。手動で100vwへ拡張したり、Googleが生成したiframeを加工したりしない。

Googleの配信判断により全幅にならない場合がある。250pxを超える広告が配信された場合のCLS、実広告の横幅、収益改善はローカルのテストでは確定できない。

公式資料: https://support.google.com/adsense/answer/9183460?hl=ja

## 公開前の検証

- 全108ファイル・994テスト通過（広告36テストを含む）。両placementの全幅属性、固定サイズ解除、無効化、二重初期化防止、通信失敗時の挙動を確認。
- 型チェック、本番ビルド（3,151ページ）、データ検証（47県・1,918自治体）通過。
- lintはエラー0件、変更箇所以外の既存警告5件。
- `npm audit --audit-level=high` は通過（high/criticalなし、既存のmoderate 10件）。依存関係は変更していない。
- 実ブラウザでのサイズ別・実広告の表示検証は未実施。本番反映とAdSense管理画面の設定変更も行っていない。

## 本番公開時の確認

1. 公開日時とコミットを記録する。PR #270公開日からの継続集計を本変更の単一条件として扱わず、広告サイズ変更の前後を分ける。
2. ランキング・都道府県詳細・自治体詳細で1枠、比較等の操作ページで0枠を確認する。
3. モバイル320/390px、タブレット768px、PC1440pxで、広告の横スクロール・切れ・本文や操作との重なりを確認。PCの表横配置も確認する。自分で広告をクリックしない。
4. 実配信時のサイズ、エラー、CLS（p75目標0.1以下）を確認する。予約高250pxで足りない場合は、実測をもとに予約高または広告サイズ方針を見直す。
5. 公開後7日・28日にAdSenseのモバイル端末別／ユニット別のページRPM、表示回数、推定収益、視認性を確認する。GA4の閲覧・回遊も確認し、アクセスや流入構成の変化を広告サイズの効果と断定しない。少数データでは判断を保留する。
6. 表示・操作の問題があれば本変更をrevertして再デプロイする。配信全体を止める場合は既存の環境変数による停止手順を使う。

自動広告・広告インテント・自動最適化の設定変更はこのPRに含めない。
