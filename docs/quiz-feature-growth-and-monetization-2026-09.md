# 統計クイズ: 流入とマネタイズの深掘り（2026-09）

前提文書: [`quiz-feature-plan-2026-09.md`](./quiz-feature-plan-2026-09.md)（コンセプトと出題設計）。
本文書はその続きで、**「で、これは流入と収益にどう効くのか」**だけを扱う。

> 注: 本セッションでは GSC/GA4 の認証情報が無く `npm run gsc:analyze` を実行できなかった。
> 以下の数値は `docs/seo/gsc-seo-implementation-plan-ctr-2026-08-28.md`（2026-08-27 実行）に
> 記録された実測値を引用している。着手前に再計測して更新すること。

---

## 1. 結論（先出し）

1. **クイズをマネタイズ施策として位置づけると失敗する。** 現在の流入規模で試算すると、
   どんな導線設計にしても**月数十円〜数百円**にしかならない（§4）。収益を動かす条件は
   流入が1桁増えることで、それを担うのはクイズではなく既存のSEOロードマップ。
2. **検索流入も主戦場にならない。** クイズが狙う「日本一の◯◯」は
   `/ranking/*` が既に担当しており、**自社カニバリゼーション**になる（§3.1）。
3. **ただし、クイズにしかない価値が1つある: 外部リンクと指名検索。**
   既存SEOロードマップの施策は全て「既に存在する検索需要を取りに行く」もので、
   **ドメインの権威を外から上げる施策が一つもない**。拡散型コンテンツはその唯一の候補で、
   効けば 1,918 の自治体ページ全部に効く（§3.2）。ここが、規模が小さい今でも
   やる理由になりうる唯一の論拠。
4. **検索流入で唯一狙えるのは「なぜ／理由」クエリ**（§3.1）。ランキングページは
   「順位」を答えているが「理由」を答えていない。統計リテラシー型の解説はその空白を埋める。
   ただしこれは**仮説であり、着手前に GSC で検証すること**。
5. **収益導線はふるさと納税一本に絞る。** 既存の `placement` prop を `"quiz"` に
   拡張するだけで載る（§5.1）。心理的にもクイズが一番相性が良い。
   ディスプレイ広告は**入れない**（§5.4）。
6. **前回の5PR計画は過剰。1PRのMVPに圧縮し、撤退基準を先に決める**（§8）。

## 3. 流入: 3チャネルの期待値

### 3.1 検索流入（期待値: 低。ただし1点だけ本命がある）

**カニバリゼーションが最大の問題。**
「空き家率 日本一」の検索意図は `/ranking/vacancy-high` が既に担当している。
同じ意図を狙うクイズページを作れば、自社の既存ページと競合して両方の順位を下げる。
これは新しいリスクではなく、`docs/seo/gsc-seo-roadmap-2026-08.md` に
「PR #127 でカニバリゼーション解消として正しい判断」と記録がある通り、
このサイトが既に一度踏んだ問題。

**したがってクイズページは、ランキングと同じクエリを狙ってはいけない。**

**唯一の本命は「なぜ／理由」クエリ。**

ランキングページは「1位は軽井沢町、70.4%」と**順位と値**を答えているが、
**「なぜそうなるのか」を答えていない**。一方、統計リテラシー型クイズの解説
（「住宅・土地統計調査の空き家には別荘等の二次的住宅が含まれるため」）は
まさにその空白を埋める。想定クエリ:

- 「空き家率 日本一 なぜ」「軽井沢 空き家 多い 理由」
- 「高齢化率 一番高い 市町村 理由」
- 「駅 一番多い 市 大阪 なぜ」

これはランキングページとカニバらない。**別の検索意図だから。**

> **着手前に検証すること**: `npm run gsc:analyze -- --days 28` の `page-query.csv` で
> 「なぜ」「理由」「どうして」を含むクエリの現状 impressions を数える。
> 需要がゼロに近ければこの根拠は消え、§3.2 の拡散だけが残る。
> **本節は仮説であり、実測で置き換えること。**

**AI Overviews / LLM 引用**: Q&A形式 + 出典明記 + `FAQPage` 構造化データは、
生成AIが引用しやすい形をしている。ここを狙うなら条件が1つある —
**クイズUIの中だけでなく、解説テキストが素のHTMLに存在すること**。
JavaScript で解答後に初めて描画される解説は、引用対象になりにくい。
テーマ別ハブ（`/quiz/{theme}`）を「クイズ形式の解説記事」として作る意味はここにある。

### 3.2 SNS拡散と被リンク（期待値: 中。ここが本命）

「空き家率日本一は軽井沢町 70.4%」は、単体で拡散する形をしている。
ただし**単発のバズは流入としては持続しない**。継続させるなら日替わり1問（Wordle型）で
再訪動機を作る必要がある。

**より重要なのは、流入そのものではなく被リンク。**

既存のSEOロードマップ（自治体詳細のtitle刷新、population系のtitle、内部リンク強化）は、
**すべて「既に存在する検索需要を、既に持っているページで取りに行く」施策**であり、
外部からリンクを獲得する施策が一つもない。ドメイン全体の評価を外から押し上げる手段が
現状ゼロという状態。

拡散型コンテンツは、個人ブログ・まとめ記事・自治体公式SNSからの引用を得られる
数少ない候補で、**効けば 1,918 ページ全部の順位に効く**。
これがクイズの唯一無二の価値であり、規模の小さい今でも着手を検討できる根拠。

一方で、**被リンクは狙って取れるものではない**（不確実性が高い）。
だから工数を絞る（§8）。

### 3.3 内部回遊（期待値: 確実だが絶対数は小さい）

`docs/seo/gsc-seo-implementation-plan-ctr-2026-08-28.md` の課題3に、
「ユーザー+76%に対し `select_municipality` が 437→374 と微減。
ランキング流入が『読んで帰る』型に留まっている」とある。
クイズは滞在と回遊を作るフォーマットなので、ここには直接効く。

ただし母数が月1,662ユーザーなので、**改善しても絶対数は小さい**。
「効くが小さい」を正しく認識しておくこと。

## 4. マネタイズの定量チェック（ここが一番大事）

ふるさと納税ファネルで試算する。

```
月間ユーザー                          1,662
 × クイズ到達率        楽観 20% / 現実 8%      →  332 /  133
 × 完走率              楽観 60% / 現実 40%     →  199 /   53
 × ふるさと納税クリック率 楽観 5% / 現実 1.5%  →   10 /    1
 × ふるなび CV率        楽観 5% / 現実 2%      →  0.5 / 0.02 件
 × 報酬（寄付1万円×約1%）                     →  約50円 / 約2円
```

**楽観ケースで月50円、現実ケースで月2円。**

支援（投げ銭）を足しても桁は変わらない。AdSense を入れたとしても、
月1,662ユーザー規模では**月数百円**が上限。

### この試算から導かれる結論

1. **クイズはマネタイズ施策ではない。** 収益を根拠に工数を正当化してはいけない。
2. **収益を動かす条件は流入が1桁増えること**であり、それを担うのは
   既存ロードマップの「自治体詳細 title 刷新」（影響1,918ページ、
   人口系クエリが**0クリック**で放置されている）のような施策。
   **期待値の桁が違う。**
3. したがってクイズは、**既存ロードマップと競合しない工数**で作るべき（§8）。

## 5. それでもクイズに載せる導線（安い順・推奨順）

### 5.1 ふるさと納税（第一候補・実装コスト最小）

**なぜクイズと相性が良いか（心理的整合）**:

- ランキングページの文脈は「**比較・選別**」。読者は住む場所を選ぼうとしている。
  この心理状態で「この自治体に寄付を」と言われても噛み合わない。
- クイズの文脈は「**へえ、南牧村ってそんな村なんだ**」という**好意的な関心**。
  ふるさと納税の動機（応援）と噛み合うのは、明らかにこちら。

**構造的にCVRが高くなるはず**:

- ランキングの `FurusatoBand` は `FURUNAVI_TOP_PAGE_URL` 着地＝`kind: "portal"`
  （移動先で寄付先を自分で探す必要がある）。
- クイズの解答画面は**その自治体のディープリンク**＝`kind: "municipal"` にできる。
  `furunaviMunicipalPageUrl(code)` が既にあるので、自治体詳細ページと同じ扱い。

**実装コスト**: ほぼゼロ。`FurusatoLink` の `placement` prop は既に
`"area" | "ranking"` の union なので、**`"quiz"` を1つ足すだけ**で
GA4 の面別CTR分析にそのまま乗る。未掲載自治体で導線が消える挙動も既存のまま。

> **着手前に確認すること（規約リスク）**: `FurusatoLink.tsx` のコメントに
> 「特定自治体を対象とした返礼品誘引広告は成果却下」とある。
> クイズで特定自治体を扱う文脈がこれに該当しないか、
> アクセストレード／ふるなびのガイドラインで**事前に**確認する。
> 返礼品に一切触れず統計データのみを示す限り問題ない想定だが、
> **成果却下は事後に効く**ため、実装前に潰しておくこと。

### 5.2 支援・投げ銭（最も安く、方針と最も整合する）

**クイズ完走直後は「楽しかった」という感情のピーク**であり、
投げ銭を依頼する最良のタイミング。「個人運営・無料・広告最小」という
このサイトの立ち位置とも最も相性が良い。

**実装コストゼロ**: `NEXT_PUBLIC_SUPPORT_URL` を設定するだけで
`SupportBanner` が点灯する。クイズの有無に関わらず、**今すぐやれる**。

### 5.3 火災保険（防災テーマのみ・提携が前提条件）

`/quiz/saigai`（ハザード・避難所テーマ）に `KasaiBand` を置けば文脈は一致する
（`/map/hazard` に置いてあるのと同じ理屈）。
ただし**現在は未提携で導線ごと非表示**。クイズのために提携を急ぐ理由はない。
提携が決まったら載せる、程度の位置づけ。

### 5.4 ディスプレイ広告（AdSense 等）— 入れない

- このサイトの唯一の差別化は**中立性と信頼性**。
  「推計を一切しない」と `/about` で宣言しているサイトのデータページに
  ディスプレイ広告が並ぶと、その主張の説得力が落ちる。
- 「クイズページ限定なら」という選択肢は理屈上あるが、
  **現規模では月数百円**（§4）。**中立性を数百円で売る**判断になる。割に合わない。
- 流入が10倍以上になってから再検討する。それまでは議題にしない。

### 5.5 やらないこと

- **自治体からの掲載料・PR記事・スポンサードクイズ。**
  「うちの町の意外な統計をクイズにしてほしい」は自治体にとってPR価値があるため
  引き合いが来る可能性はあるが、金銭を受け取った時点で
  「政府統計を中立に整理している」という主張が崩れる。統計サイトの生命線。
- **煽り型の出題**（「住みたくない街」「ヤバい市町村」）。
  拡散はするが、`lib/prefAggregates.ts` が明記する
  「高い＝良いという含意を持たせない」姿勢と正面から矛盾する。

## 6. 計測設計（撤退・継続を判断できる最小構成）

`lib/analytics.ts` に追加（既存の命名規則に合わせる）:

```ts
trackQuizStart({ theme, questionCount })
trackQuizAnswer({ theme, questionId, correct, position })
trackQuizComplete({ theme, score, questionCount })
trackQuizResultClick({ municipalityCode, questionId })
```

加えて、`FurusatoLink` の `placement` に `"quiz"` を追加する（型の1行）。
これで `furusato_link_impression` / `_click` が面別に取れ、
**クイズ面のCTRを `area` / `ranking` と直接比較できる**。§5.1 の
「クイズの方がCVRが高いはず」という仮説を、推測でなく実測で検証できるようになる。

**判断に使う指標**:

| 目的 | 指標 | 取得元 |
|---|---|---|
| 拡散したか | referral / social セッション数、新規ユーザー比 | GA4 |
| 被リンクが増えたか | 参照ドメイン数 | GSC リンクレポート |
| 「なぜ」クエリを取れたか | 該当クエリの impressions / clicks | `gsc:analyze` |
| 回遊が増えたか | `quiz_result_click` → `select_municipality` | GA4 |
| 収益導線が機能したか | `placement="quiz"` の furusato CTR（area/ranking と比較） | GA4 |
| 問題の質 | 問題別の正答率（90%超＝簡単すぎ / 25%前後＝ダミーが機能していない） | `quiz_answer` |

| 施策 | 影響ページ数 | 期待効果 | 工数 | 確度 |
|---|---:|---|---|---|
| 自治体詳細 title 刷新 | **1,918** | 人口系・家賃系クエリの**CTR 0.00%** 群を起こす | 小（`generateMetadata` のみ） | **高** |

**既存ロードマップを先に進めるべき**であることは、数字を並べると明白。
クイズはその裏で**小さく**走らせる位置づけにする。

## 8. MVP の圧縮（前回の5PR → 1PR）

§4 の期待値から逆算すると、前回計画の PR-1〜5 は過剰。**1本に圧縮する。**

**スコープ（これだけ）**:

- `/quiz` 1ページのみ。テーマ別ハブ（`/quiz/{theme}`）は**作らない**。
- **日替わり1問**（Wordle型）。再訪動機を作るのが目的。
- 手書き20問。答えと選択肢はビルド時計算（前回文書 §6.4 の通り）。
- OG画像（`/api/og/quiz`）と共有ボタン（`ShareButton` を再利用）。
- 解答後: 自治体詳細へのリンク + ふるさと納税（`placement="quiz"`）。
- GA4 イベント4種（§6）。

**日替わりの実装方針**: SSG のまま、全20問をクライアントに配って
**日付シードで1問選ぶ**（ISR も再ビルドも不要）。
副作用として**ソースを見れば答えが分かる**が、カジュアルなクイズなので許容する。
（隠したいなら ISR か API 経由になり、工数が跳ね上がる。割に合わない。）

**やらないこと（MVPでは）**: テーマ別ハブ、地図クリック型、並べ替え型、
県別クイズ、スコアランキング、ユーザー投稿。

**撤退基準を先に決める**（これが最重要。決めずに始めると惰性で拡張してしまう）。
リリース後2ヶ月の時点で:

- referral/social セッションが有意に増えていない **かつ**
- 参照ドメインが増えていない **かつ**
- `quiz_result_click` がセッション比で伸びていない

→ **テーマ別ハブ以降には進まない。** `/quiz` 1本を維持するか、畳む。
逆にどれかが動いていれば、動いた方向にだけ拡張する
（拡散が効いた→OG/日替わりを磨く、「なぜ」クエリが取れた→テーマ別ハブを作る）。

## 9. 着手前にやること（順番通り）

1. **`NEXT_PUBLIC_SUPPORT_URL` を設定する。** コード変更ゼロ、工数ゼロ、今すぐ。
   クイズの成否と無関係に、現状「収益導線が1本しか点いていない」状態が改善する。
2. **`npm run gsc:analyze -- --days 28 --compare` を実行し、
   「なぜ／理由／どうして」を含むクエリの現状を数える。**
   §3.1 の本命仮説が成立するかどうかがここで決まる。
   需要がゼロに近ければ、クイズの根拠は §3.2 の拡散だけになり、
   MVP をさらに小さくする（あるいは見送る）判断があり得る。
3. **アクセストレード／ふるなびのガイドラインを確認する**（§5.1 の規約リスク）。
4. **撤退基準の具体的な数値を決める**（§8）。
5. 上記が通ってから、MVP 1PR に着手する。

## 10. この文書の要約（1段落）

統計クイズは、**収益施策としては現在の流入規模で成立しない**（月数十円）。
検索流入も、既存ランキングとのカニバリゼーションを避けると
狙えるのは「なぜ／理由」クエリだけで、これも未検証の仮説。
一方で、**外部リンクを獲得しうる唯一の施策**であり、効けば全1,918ページに波及する。
したがって「小さく作って2ヶ月で判定する」のが正しい形であり、
既存SEOロードマップ（期待値の桁が違う）を止めてまでやることではない。
収益導線はふるさと納税に絞り（`placement` に `"quiz"` を足すだけ）、
ディスプレイ広告は入れない。
