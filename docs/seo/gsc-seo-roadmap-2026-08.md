## 最優先: 自治体詳細ページの title 刷新

**4つの調査のうち3つが独立に同じ結論に到達した唯一の項目。**

### 現状（`app/area/[pref]/[city]/page.tsx:94-98`）

```
{自治体名}の住みやすさ・在留外国人割合X.XX%（全国N位） - KurashiMap
```

在留外国人データがある自治体（＝ほぼ全件）はこの形式で固定。**title に人口・家賃・都道府県名が一切入らない。**

### 根拠

| 検索意図 | impressions | CTR | 平均順位 | titleに該当語 |
|---|---:|---:|---:|---|
| 外国人系 | 441 | 1.13% | 8.9 | ✅ あり |
| **人口系** | **152** | **0.00%** | 21.6 | ❌ なし |
| **家賃・相場系** | **~270** | **0.00%** | 31〜43 | ❌ なし |

- 「菊陽町 人口」43 imp・平均10.5位・**0クリック** → title に「人口」が無い
- 「輪島市 家賃相場」「青森市 家賃相場」等は `/area/{pref}` ハブに31〜43位で誤着地。正解であるはずの自治体詳細ページ（その市の `rent.value` を持つ）が浮上しない
- 加えて `displayName` が県をまたいで重複する自治体が26種・**59ページ**（池田町×4、朝日町/美郷町/南部町/美浜町/美里町×3…）。title に県名が無いためSERPで区別できない

### 対応

title に人口・家賃を入れ、県名で曖昧性を解消する。外国人割合は description に移す（description には既に `人口{pop}人` が入っており、外国人の実数値も保持できる）。

- 変更ファイル: `app/area/[pref]/[city]/page.tsx` の `generateMetadata` のみ（メタデータ変更で本文・UIは触らない）
- 使用フィールド: `m.population` / `m.rent.value` / `prefName`（すべて既存）
- 影響範囲: 全1,918ページ

**注意**: 現在の title は2026-07のGSC分析に基づく意図的な設計（コメント参照）で、外国人系のCTR改善が目的だった。今回それが「他の意図を締め出す副作用」を持つと判明したため、外国人系の実績（441 imp・平均8.9位）を落とさない形にする必要がある。実装時は外国人系の順位・CTRも計測対象に含める。

## P1: `{県} 家賃相場` の受け皿を作る（PR #127 の副作用対応）

PR #127 で `/area/{pref}` の title から「家賃相場ランキング」を除去したのはカニバリゼーション解消として正しい判断だったが、**結果としてこの意図を担当するページが無くなった。**

- `/area/{pref}` が money 系 **1,150 imp を平均32.9位・0クリック**で吸収（＋`other` カテゴリの `{県} 相場` 約660 imp）
- `/ranking/rent-cheap|high/{pref}` は平均7.9〜8.3位と好調だが、「安い/高い/ランキング」表現でしか出現せず、**「相場/平均/目安」では出ない**
- 実クエリ例: 「家賃相場 石川県」26 imp・30.8位、「石川県 家賃相場」21・32.7位、「長崎県 家賃」19・42.2位、「兵庫県 家賃相場」17・33.6位、「家賃平均 富山」16・26.2位

### 対応案

`components/MetricMapHub.tsx`（`MetricHubConfig` で設定駆動）を土台に **`/map/rent/{pref}` 47ページ**を新設（H1「{県}の家賃相場マップ」、県内中央値/最小/最大＋全市区町村表）。rent 専用ページを手書きせず、**`app/map/[metric]/[pref]` として `MAP_METRICS` × `PREFS` で生成し、当面 rent のみ有効化する**（地価・人口増減・外国人割合も同じ「相場/平均」ギャップを持つため、メカニズムを一般化しておく）。

- 使用フィールド: `m.rent.value` / `m.rent.asOf` のみ
- 「相場/平均/目安」≠「安い/ランキング」なので `/ranking/rent-cheap/{pref}` とカニバらない
- `/map/foreign-ratio` が同テンプレートで **CTR 18.42%** の実績あり
- ただし `MetricMapHub` はセクション一覧を描画するだけで、県内中央値/最小/最大と全市区町村表は新規コンポーネント。`app/map/rent/page.tsx` も全国 `HomeShell` + `listSummaryAcrossPrefs()` のため県スコープ化が要る。「テンプレート流用」ではなく新規実装として見積もること

※ より低コストな代替案（`/ranking/rent-cheap/{pref}` に相場サマリーを追加）もあるが、PR #127 で閉じたばかりのカニバリゼーションを再び開くリスクがある。

**未解決**: 下記「都道府県ハブのコンテンツ拡充」の県サマリーも家賃を含むため、本案と県レベルで重複する。同一フェーズで両方投入すると本ドキュメントが問題視しているカニバリゼーションを自ら再現するので、**どちらが `{県} 家賃相場` の受け皿かを着手前に一本化する**こと。

## P1: 自治体 Exposure Rate — まず診断、施策はその後

### 調査結果: コード側に欠陥は無い

技術チェックは**すべてクリーン**だった:

- `app/sitemap.ts` は全1,918自治体を出力（総URL数 ≤2,646、Googleの50k上限に対し余裕）。除外フィルタなし
- `app/robots.ts` は `/api/` のみ disallow。`/area/` はブロックされていない
- `generateStaticParams` は `listAllAcrossPrefs()` で全1,918件をカバー。canonical は全ページ設定済み。noindex は `/search` と not-found のみ（意図通り）
- クロール深度は全自治体で**2**（トップに47県リンクが初期HTMLに存在 → 県ハブの表に全自治体＋行政区）
- 兄弟ページからの被リンク数は**中央値16・平均17.4**、ゼロなのは7自治体のみ
- 政令市の行政区は不利ではない（人口を統制すると市区町村と同等）
- データが薄いページが不利という証拠も無し（人口5k-20k帯で `hasRent` あり40.8% vs なし38.6%）

### 原因の内訳

**需要 約55〜60%**: 人口別の露出率は単調に上昇（<5k 27.0% → 5-20k 39.2% → 20-50k 43.1% → 50-100k 52.2% → 100-300k 62.3% → 300k+ 78.9%）。露出ありの人口中央値44,364 vs 露出なし17,241（2.6倍）。人口2万人未満の846自治体は需要の下限であり、**ここに労力を割く価値は無い**。

**インデックス被覆 約40%**: ただし300k+でも**78.9%止まり**で、需要では説明できない。ゼロ表示の大規模自治体:

| 自治体 | 人口 |
|---|---:|
| 仙台市 | 1,096,951 |
| 浜松市 | 765,750 |
| 練馬区 | 761,587 |
| 新潟市 | 759,618 |
| 相模原市 | 712,105 |
| 松戸市 | 496,714 |

**人口10万人以上で表示ゼロが142件、5万人以上で264件。** サイト構造は正しいので、制約は8週齢ドメインのクロールバジェット／インデックス選定（2026-07監査の「検出-未登録866＋クロール済-未登録239」と整合）。

なお都道府県別の格差は人口調整後も残る（間接標準化 SIR: 下位7県0.56 / 上位4県1.19、青森0.45・広島0.49 vs 大分1.45）が、**「地方だから」ではない**（最も人口規模の小さい北海道が SIR 1.21）。コードとデータからは原因を特定できなかった。

### 【2026-08-10 追記・訂正】URL Inspection API で診断した結果、上の「インデックス被覆 約40%」は**誤り**だった

GSC URL Inspection API（サービスアカウントの既存権限＝制限付き・`webmasters.readonly` でそのまま利用可）で、
表示ゼロのページを人口帯別に層別サンプリング（計60件）した実測:

| 群 | n | Submitted and indexed | 未インデックス | 最終クロール（中央値） |
|---|---:|---:|---:|---|
| 表示0・人口10万人以上 | 25 | **96%** | 1件（Discovered） | 2026-06-21 |
| 表示0・人口2〜10万 | 15 | **80%** | 2件（Discovered/Crawled） | 2026-06-21 |
| 表示0・人口2万未満 | 10 | **100%** | 0件 | 2026-07-17 |
| ★対照: 露出あり | 10 | **100%** | 0件 | 2026-07-29 |

※ 人口2〜10万の1件は HTTP 503（APIの一時エラー）。全件実行時はリトライが必要。

**表示ゼロのページは、ほぼすべて既にインデックスされている**（サンプル全体の約93%）。
浜松市77万・練馬区76万・相模原市71万・東広島市19万・八戸市22万はいずれも `Submitted and indexed` で、
唯一 `Crawled - currently not indexed` だったのは仙台市のみ。

したがって課題は**インデックス被覆ではなく、インデックスされているのに
どのクエリでも上位に出ないこと＝競争力（関連性）**である。上の「約40%はインデックス被覆」という
見立ては取り下げる。

**打つべき手は「クロール性・内部リンクの改善」ではなく「実際に検索されるクエリに対して
ページを競争力のある内容にすること」。** 自治体詳細ページの title に人口・家賃が
1語も入っていなかった問題（本ドキュメント冒頭の最優先項目、PR #129）は、まさにこの方向の施策である。

### ただし副次的な発見: 表示ゼロのページは7週間クロールされていない

最終クロール日の中央値は、**表示ゼロ群 2026-06-21 に対し露出あり群 2026-07-29**。
サイト公開は2026-06-18なので、表示ゼロのページは**公開直後に一度クロールされたきり**である。
これは低評価の「結果」であって原因ではないが、運用上は重要な意味を持つ:

> **PR #129 / #130 の title・本文変更をデプロイしても、当該ページが再クロールされるまで
> 検索結果には反映されない。**

かつ `app/sitemap.ts` の `lastModified` は設計上**データの実 vintage（asOf）由来**で、
テンプレート変更では動かない（`lib/dataFreshness.ts` の冒頭コメント参照。毎ビルド `now` を
入れると「常に全更新」のノイズ信号になるため、意図的にこうしてある）。
つまり今のままでは Google に再クロールの手がかりが無い。

**推奨（要判断）**: `lib/dataFreshness.ts` に「テンプレート最終改訂日」の定数を置き、
`lastModified = max(データasOf, テンプレート改訂日)` とする。テンプレートを実際に
変更したときだけ手で日付を進めるので、「毎ビルド動く」ノイズにはならず、
かつ実際にページ内容が変わったことを正しく伝えられる。

なお Google は IndexNow 非対応のため `npm run indexnow` は Bing 系にしか効かない。
GSC UI の「インデックス登録をリクエスト」は1日十数件程度の制限があり1,918ページには使えない。

### 残る未解明点

都道府県別の格差（SIR 0.45〜1.45）は、インデックス被覆で説明できないことが分かった以上、
地域ごとの検索需要量の差である可能性が高い。外部のキーワードボリュームデータが無いと確認できない。

## P1: 都道府県ハブのコンテンツ拡充

`/area/{pref}` は 2,858 imp・14クリック・CTR 0.49%・平均31.7位で**最弱のページタイプ**。PR #127 はカニバリゼーションを解消したが、構造的な拡充は未着手。

money 系クエリを除くと、残る最大のクラスタは **「{県} 住みやすさ」24件・236 imp・平均35.6位**。**このページタイプだけが該当**しており（自治体ページは5 imp）カニバリの心配が無い。title には既に「住みやすさ」が入っているので、**35位付近＝コンテンツの薄さ**が原因。

### 対応案（効果順）

1. **県サマリー（県平均＋全国◯位）** — `lib/areaStats.ts` の `getAreaStats().byPref` が家賃・地価・人口増減率・空き家率・人口密度の47県値を既に返す。`lib/foreignStats.ts` の `prefForeignAvgs(stats)` も県別値を返す（ただし `getForeignStats()` の結果を渡す必要があり、返すのは `prefAvg` の1指標のみ）。**これらをソートするだけで「全国◯位/47」が新規データ無しで導出できる。** 47ページが本当に異なる内容になる
   - ※ 順位を主張する土台としては**自治体を1票とする単純平均が妥当か**を先に決めること（港区と檜原村が同じ重みになる）。PR #130 はこれを理由に単純平均を採らず県内中央値を用いている
2. **関連ランキングを全指標に拡張** — ランキング×47県のページはデータが該当する県ぶん既に存在するのに、ハブからは**14指標中4つしかリンクしていない**。`RANKINGS`（`lib/rankings.ts`）を全件ループするだけ
   - 47県すべてに14ページ揃うわけではない。`app/sitemap.ts` も県ハブも `qualifies` / `rankBy(...).length > 0` で絞るため、14×47=658 は上限
3. **県内自治体の「住みやすさ」ランキング** — `lib/livabilityScore.ts` の既存の自治体スコアで県内順位を出す（下記 livability 節参照）
4. 災害・子育て・インフラのサマリーカード（`hazard`/`waitlistChildren`/`amenities`/`shelters` を県内集計）
5. 県版FAQ＋FAQPage構造化データ（`lib/faq.ts` は自治体専用なので県版を追加）

## P2: GSC計測ツールの拡張

現状で**存在する**のは URL単位の期間比較（`comparePages`）と、サイト全体の前期間合計（`analyze.ts` の `site: totalMetrics(pageRowsPrev)`）・自治体単位の前期間比較（`aggregateMunicipalities` → `classifyMuniStatus`）。ただし**CSVに出ているのは派生サブセット（positionImprove / positionDecline / newVisibility）だけで、`pageDiffs` 全体は出力されない**。**欠けている**のは: page-query の期間比較、pageType別の期間比較、Exposure Rate 推移、ranking template別集計、CTR改善対象のbefore/after、施策URLセット追跡。

### 設計判断: レポートdirの比較ではなく、任意期間の再取得

`reports/gsc/` は **gitignore されている**ため、過去のレポートdirは新規クローンやCIには存在しない。一方 **GSC APIは約16ヶ月データを保持**しており、`api.ts` の `QueryOptions` は既に任意の `startDate`/`endDate` を受け取れる。したがって「PR #126 直前の期間」はいつでもAPIから再構成できる。

→ `--baseline=YYYY-MM-DD..YYYY-MM-DD` と `--since=YYYY-MM-DD`（デプロイ日を挟む対称N日窓を自動算出）を追加するのが最小変更。両期間が同一の分類・集計コードを通ることも保証される。

### 施策URLセット追跡

`scripts/gsc/url-sets.json`（gitignore されない、かつ消費側の `scripts/gsc/` 配下。クエリ分類を持つ `scripts/gsc/config.ts` と同種の設定であり、`docs/` に機械可読の実行時入力を置かない）に、変更と同じPRで人が追記する形式:

```json
[{ "name": "pr-126-population-rankings", "pr": 126, "since": "2026-08-10",
   "include": ["/ranking/population-most", "/ranking/population-most/*", "/ranking/*/*"] }]
```

PR #126 は約658 URL、PR #127 は47県ハブ全部に影響するため、**グロブパターンが必須**（URL配列の直書きは維持不能）。

想定規模: 約350行の追加、新フラグ未指定時は既存挙動を一切変えない。

## P3: livability — 都道府県版スコアは**作らない**

### 判断

`lib/livabilityScore.ts` は単一の `Municipality` を**絶対値しきい値**（駅30以上、医療80以上、保育80以上、全国固定の家賃帯50k/55k/60k/65k）で5軸評価する。都道府県平均には3つの致命的問題がある:

1. **分母が行ごとに違う** — 評価軸数は自治体ごとに0〜5（ハザード/インフラ対象外、待機児童非公表がある）。県平均は**異なる軸セットで算出されたスコアの平均**になり、県間で比較できない
2. **規模バイアス** — 北海道195自治体 vs 香川17自治体の単純平均は「政令市があるか」を測っているだけ。人口加重しても都市化度で並び替わるだけ
3. **出典に無い順序を主張することになる** — honesty方針は欠損を推計で埋めることを禁じているが、47県の総合「住みやすさランキング」は**観測値ではない構成概念を事実として提示する**もので、より重い。既存14ランキングは**すべて単一の観測指標**であり、この設計を破ることになる。`/about` が慎重に避けている「都道府県の優劣」の主張そのもの

### 代替案（実施する）

`/area/{pref}` に**県内の市区町村を既存の自治体スコアでランキング**するセクションを追加する。ランク付けの対象が自治体のままなので新しい構成概念を作らず、「{県} 住みやすさ ランキング」に直接応えられる。既存の「目安であり優劣ではない」注記は維持する。

## P3: safety（治安） — 恒久的にスコープ外

`CLAUDE.md:50` / `README.md:146` /（利用者向け）`app/about/page.tsx:147,243` の3箇所で確認済みの法務方針。**「保留」ではなく優先順位リストから削除すべき**項目で、79 imp・0クリックは正しく未提供のまま。

`scripts/gsc/config.ts` の `safety` クエリカテゴリは**除外フィルタとして有用**なので残す（対応可能な機会として集計に混ざらないようにするため）。

なお当サイトは災害リスクデータ（浸水・土砂・液状化・津波・高潮、指定緊急避難場所）を既に公開しているが、これを治安クエリへの回答として位置づけ・タイトル付け・内部リンクすることは、データが裏付けられない安全性の主張になるため**行わない**。
