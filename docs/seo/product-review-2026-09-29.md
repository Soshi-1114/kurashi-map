## 5. 改善案と実施順

以下の工数・基準は提案であり、実績や統計的有意性を保証する数字ではない。1人で担当する前提で、初回は合計20時間を上限とする。新軸・新ページ種別は[採用基準](../new-metric-criteria.md)の10月中旬までの凍結を維持する。

### P0: 評価指標を直す（計測担当、4時間目安）

成果を「条件変更回数」から「結果を見て詳細・比較へ進んだセッション」に変更する。比較では2自治体以上の表示セッションを成果とする。地図は自治体選択セッションと、その後の比較・詳細遷移を分ける。ASPの確定成果は別表で扱う。

- 9/29のローカルコミット`8eff442`に診断結果表示・スクロール・比較クリックが実装済み。取得期間は9/28までなので、そのイベントがレポートにないことは不具合の証拠ではない。本番反映日時・受信・定義を確認してから観測開始日を固定する。
- `shindan_result_impression`は結果生成時の発火、`shindan_result_scroll`は結果sectionの25%交差という実装。後者が長いsectionでは最初の結果を見た事実を取り逃がさないか、モバイルで確認する。
- 同一セッション・同一端末区分で入口→操作→結果視認→詳細/比較のファネルを作る。GA4探索で利用可能ならセッション単位で集計し、現状の集計表を割った疑似CVRで代替しない。
- 内部確認操作を除外できる運用、`tool_source`欠損、比較の`count`がURL復元前に0で送られないかを確認する。後者は未検証の技術仮説。
- title試験のURLセットと本番反映日を固定。ローカルの実装日をSEO試験開始日にしない。

**完了条件:** テスト操作を特定でき、診断・比較の各段階を同じ母数で測れる。既存実装を重複して作らない。

### P1: 人口ランキング3ページの検索結果訴求を改善（SEO担当、4時間）

対象は人口数の全国・北海道・兵庫。28日合計17,043表示 / 97クリック / CTR 0.57%。個別では全国7,564 / 45、北海道5,420 / 28、兵庫4,059 / 24。順位は8〜9位前後。

北海道の「北海道 人口 ランキング」は627表示0クリック、「北海道人口ランキング2026」は209表示0クリック。人口と一覧・年次を求める需要は実在する。検索実査でも全市町村・掲載数・年次を明示した競合が複数あった。ただし今回の検索ツールはユーザーの実際のGoogle結果やAI要約表示を再現するものではなく、低CTRの原因確定には使わない。

変更案は、取得済みの統計年・掲載自治体数を短いtitleの前半に寄せる。北海道の例: `北海道の市町村人口ランキング｜全179自治体・2025年国勢調査`。実データ年を2026に見せかけない。全国版は上位100件など実際の掲載範囲と一致させる。titleだけを先に試し、description・本文・広告配置を同時に変えない。

**評価:** 28日、同一URL×クエリ×デバイスで順位帯も比較。順位・需要が動いた場合はtitle効果と断定しない。CTR +0.3ptを実務上の採用目安とし、クリックと不確実性も見る。3ページ合計CTRが1%なら約170クリック、現状比+73という試算になるが、これは表示数固定の感度計算であって予測ではない。

自治体詳細全体のCTRを+0.5pt改善しても同じ表示数なら約44クリック増。まず大きな母数のランキングを優先する。自治体詳細4件の既存試験は継続し、足立区は人口系と検索意図が違うため補助比較と扱う。人口系で順位・露出が近い未変更ページも対照に加え、4ページの結果だけで1,918ページへ展開しない。

### P1: ランキングを「調べた後に比較できる」ページへ部分刷新（UI担当、6時間）

既に上位3件比較・行別比較・診断・関連ランキングなどの導線がある。CTAを足す施策ではなく、流入上位の既存ページだけで、主操作を「この地域の自治体を比較」、補助操作を「地図で見る」に整理する。統計だけを調べる利用者には表の閲覧で目的が完了するため、全員を住み替え診断へ誘導しない。

第1段階は、北海道・兵庫など県内比較の文脈が明確な面で、上位3件比較の文言に対象自治体名を明示する。人口の全国ランキングで自動的に上位3都市を比較させることが、住まい選びに適切とは限らない。

第2段階の機能拡張候補は、表で任意の2〜3自治体を選ぶ比較と、表内の自治体検索。前段の比較利用が確認できた後に限定導入する。比較選択状態はURLで保持し、新しい静的URL群は作らない。地図・トップへフルMunicipalityを載せる設計変更もしない。

**評価:** 対象ページを見たセッションのうち比較2件以上表示まで進んだ割合。導線クリック率と比較到達率を分ける。変更前後で各300対象セッションか28日までを最初の観測窓とし、改善方向が不明なら全体展開しない。300件は十分な検出力の保証ではなく、早すぎる判断を防ぐ最低観測目安。

### P2: 診断は結果到達の改善を1回だけ試す（UI担当、P0後・4時間）

350回/22人の条件変更に対し結果詳細クリックは2件。考えられる原因は、結果が下にあり気づかれない、結果を見ただけで完了、結果の説明不足、計測の不足。現時点では選別できない。

結果視認が少ない場合は「条件に合う街がN件あります・結果を見る」を条件操作直下に表示し、明示的な操作で結果へ移動できるようにする。視認されるがクリックされない場合は、上位3件に実データによる適合理由と不向きな点、詳細ボタンを示す。2つを同時に実装しない。推定の住みやすさや説明を生成して埋めない。

**評価:** 内部テスト除外後、結果視認セッション→詳細または比較への遷移率。結果視認100セッションを目安に判断するが、11/24までに集まらなければ追加開発を止める。少数データのまま「有意差なし＝無効」とはしない。利用が少ない機能へ工数を追加しないという判断である。

### P2: 収益導線は文脈の合う面だけ残す（事業担当）

ふるさと納税は1,299人が視認して1人しかクリックしておらず、現在の訴求との適合は弱い。主力ランキングで広告面積・掲載数を増やさない。まず既存placement別に分解し、弱い場所の目立つ帯は縮小候補とする。収益を確認せず一括削除もしない。

火災保険はハザード確認面で現状維持、電気代は更新・保守に限定。電気代の試算利用者4人、GSC0クリック/30表示という母数ではプラン追加や新規SEO記事への投資根拠は弱い。条件付きで1回導線を検証し、低利用が続けばナビゲーション上の優先度を下げる。

`/map/hazard`は140人・平均2分35秒の利用があるため残す。ただしこの滞在時間から保険購買意向を推定しない。公開ページでも自治体全域のリスクと個別地点のリスクを区別しており、この説明を維持する。

## 6. 継続・縮小・撤退の判定

| 選択肢 | 今回の判断 | 条件 |
|---|---|---|
| 全面刷新 | 見送り | 検索流入が伸びており、全面変更の優位性を示す事実がない |
| 新指標・新ページ拡張 | 凍結継続 | 10月中旬以降もSERP・GSC需要・カバレッジの3基準を満たす場合のみ |
| ランキング＋比較・地図へ集中 | 推奨 | 検索需要と実利用の両方がある |
| 診断・電気の追加開発停止 | 条件付きで実施 | 1回の限定検証後も利用者が集まらなければ停止 |
| 保守のみへ縮小 | 11/24に判断 | 限定改善で成果行動が増えず、採算または許容作業時間も満たさない |
| サービス全体撤退 | 現時点では根拠不足 | 採算不足が続き、無料維持・資産保有の価値も費用を上回らない場合 |

収益目的なら、月次の`ASP承認済み報酬＋その他確定収益−インフラ等の現金費用−運営時間×評価時給`を判定表にする。評価時給・許容赤字・目標利益は事業主が決める。クリック数だけで損益分岐点や月収を予測しない。11/24時点で2回の28日レビューを行い、マイナスが継続し改善経路も見えなければ新規開発を終了し保守のみへ移す。

公共サービス目的なら現金費用と保守時間の上限を決め、その範囲でランキング・地図を維持する。収益未成立だけを撤退理由にしない。実績資産目的なら更新可能な範囲へ縮小し、公開データの基準日を明示する。

ページ撤去はSEOクリックだけで決めず、内部回遊・被リンク・維持費を確認してから行う。全体撤退の場合も、再利用可能なコード・データ出典・集計手順を保存し、収益契約や利用者への案内を整理する。
