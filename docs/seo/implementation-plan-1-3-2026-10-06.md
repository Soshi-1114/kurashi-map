# 再分析に基づくタスク1〜3の実装計画

作成日: 2026-10-06。根拠: [再分析](reanalysis-2026-10-06.md)。

2026-10-06 更新: デプロイ後、依頼者から対象2ページの比較リンクが他リンクに埋もれ見つけづらいという直接の利用所感があった。このため当初予定した14日間の同配置ベースラインを待たず、CTAをランキング上位3件の直後へ移し、独立した強調枠で示す。変更前イベントは本番利用の観測がないため比較対照として扱わない。配置変更後を新しい`compare-cta-placement-2026-10` treatmentとして計測する。

本計画の番号は①成果計測の本番確認、②ランキングから比較への利用検証、③対象ページを絞った改善を指す。[旧計画](improvement-plan-1-3-2026-09-29.md)の「②3ページtitle試験、③比較導線改善」は本計画へ置き換える。計測コードは[PR #225](https://github.com/Soshi-1114/kurashi-map/pull/225)で本番反映済み。配置改善は本書冒頭の更新に従い、別PRで実装・評価する。

## タスク1：成果計測を成立させ、本番で確認する

### 現状

- 作業ツリーに`compare_ready`、`compare_view`、CTA視認/クリック、診断の視認対象修正、送客元allowlistがある。既存実装をレビューして補完し、作り直さない。
- CTAイベントには対象ページ・実験ID・variantがある。一方、比較成立/視認には件数・`tool_source`しかなく、大阪/福岡や変更前後を比較先で判別する情報が不足している。
- 診断結果の視認定義とパラメータ名が変わるため、過去の計測と無条件に接続しない。
- ローカルのタイトル試験差分は計測リリースから分離する。北海道・兵庫のtitle案は公開しない。

### 実装手順

1. HEAD・既存差分・本番SHA/公開日時を確認し、計測とSEOの差分を分離する。既存の未コミット作業や利用者のファイルを一括で戻さない。
2. イベント仕様を固定する。生成・視認・クリック・着地・比較成立をそれぞれ別の事実として記録する。
3. 比較リンクに入口識別情報を付け、着地で検証してメモリ内に保持する。`origin_path`は対象2パス、実験IDとvariantは定義済み値だけ許可する。任意URLや自由入力は送信しない。既存の`from`/`ToolSource`契約を保つ。
4. CTA・`tool_entry`・`compare_ready`・`compare_view`へ同じ入口識別情報を付与する。対象変更によるURL更新でも入口情報を保持し、新しい直接訪問には引き継がない。永続保存は導入しない。
5. 変更する計測へ`measurement_version`を付け、公開日と意味の変更を記録する。比較成立は2件以上の有効コードの取得完了時、視認は完成した表の先頭の50%以上交差時とする。対象順序だけの変更・再描画による重複を抑える。
6. 診断は生成・先頭結果視認・詳細/比較クリックを分ける。条件変更時の重複抑制、結果0件、初期表示の扱いを仕様化し、実行イベントと分母を一致させる。
7. GA4の既存定義・タイムゾーン・内部アクセス・PV設定を確認する。必要な低カーディナリティのカスタム定義を重複なく追加し、登録日時を残す。
8. プレビューで発火を確認し、本番反映後にイベント名・パラメータ・通常レポートへの反映を確認する。テストアクセスは識別して評価から除く。

### 集計契約

| 指標 | 分母 | 分子 |
|---|---|---|
| 比較着地後の成立率 | 2件以上の有効コードで比較に着地 | その後に比較成立 |
| 比較着地後の視認率 | 上記の着地 | その後に表視認 |
| ランキング経由成果率 | 対象ランキングを閲覧 | 対象CTA経由でその後に比較表視認 |
| 診断結果視認率 | 定義済みの診断実行 | 同じ計測版でその後に結果視認 |
| 診断結果遷移率 | 結果視認 | その後に詳細/比較クリック |

同一セッションとイベント順序を確認できる集計を優先する。GA4探索/API・既存エクスポートで実現できるかを先に検証する。単なるイベント数の割り算では代用しない。セッション単位が取得できなければ、ユーザー単位への変更と限界を明記して評価仕様を修正する。新しい分析基盤をこの20時間枠で新設しない。

### 完了条件・検証

- 0/1件、重複/無効コード、取得失敗・loading中に比較成果が発火しない。2/3件成功時に成立し、画面外では視認が発火しない。
- 直アクセス・内部遷移・対象追加/削除・順序変更・再描画で送客元と重複抑制が正しい。
- PC/モバイルの表と診断カードで実際の発火を確認する。
- 本番SHA、計測版、GA4登録/受信日、評価に使える集計方法を記録する。ここまでで完了。ローカルのテスト通過だけでは完了扱いにしない。

変更候補: `lib/analytics.ts`、`lib/siteNav.ts`、`lib/useToolEntry.ts`、`components/compare/CompareClient.tsx`、`components/shindan/ShindanClient.tsx`、`components/ranking/TrackedCompareLink.tsx`、対象ランキングページ、計測文書・関連テスト。

## タスク2：ランキングから比較への利用を検証する

### 基準観測

対象は既存の`/ranking/population-growth/osaka`と`/ranking/population-growth/fukuoka`。PR #225のデプロイ後に有効な変更前利用が確認できなかったため、旧配置の前後比較は成立しない。依頼者の実利用所感を根拠に配置を変更し、新experiment IDで変更後の受信を観測する。

対象ページ閲覧、CTA視認/クリック、比較着地、成立、表視認を対象URL・variant・デバイス別に記録する。検索順位や流入構成も併記する。集計レスポンスと期間・フィルタ・集計単位を非機密のレポートとして保存する。

### 限定UI変更と分岐

- 比較着地後に成立しない場合は、取得・コード・リンクの不具合を先に修正する。CTA訴求では解決しない。
- CTAが見られていない、または見られても押されない場合は、対象2ページだけで比較目的と対象名を明示する。
- 成立しても表が見られない場合は、比較先の表示位置・loading後のレイアウトを調べる。対象2ページの前後比較と混ぜず、別修正として記録する。

CTA候補は「人口増加率 上位3自治体を比較」と現在の上位3自治体名。名前・コードは既存データから取得し、リンク先の自治体と一致させる。「住みやすさ」の評価へ言い換えない。既存のランキング本文・title・広告は固定し、全表をクライアント化しない。

### 評価・完了条件

変更後28日を観測し、同じ定義で前後を比較する。各期間300対象セッションは観測量の目安であり、有意差の保証ではない。成果率の相対20%改善は採用候補の目安に留め、分母・成果件数・絶対差・流入構成を併記する。前期成果0件なら相対率を使わない。

母数不足は最大56日で観測を終了し「判断保留・全体展開なし」とする。試験途中で対象URLを追加しない。技術的不具合は戻すが、短期の数クリック差で採否を決めない。

完了条件は、基準集計の保存、原因に応じた限定変更、320/375/390px・PC・キーボードの確認、変更後評価と採用/保留/見送りの記録。任意自治体検索の拡張は、この成果確認後の別案件。

## タスク3：検索意図を確認し、既存ページを絞って改善する

### 調査・対象選定

1. 全国人口ランキングを第一候補とする。北海道・兵庫は自然改善中なので変更を保留し、観測対象として残す。
2. 全国版の代表クエリ、デバイス別順位/CTR、前後に共通するクエリ、実検索titleを確認する。GSCの全体device集計を対象URLの値として使わない。必要なら対象URLでフィルタした読み取り集計を追加する。
3. 自治体詳細は、両期間に表示された782ページから当期表示上位を抽出し、ゼロクリック・低CTR・順位帯・検索意図を照合する。初回の詳細確認は最大5ページ、公開する修正は最大3ページとする。件数は工数制約で、効果の保証ではない。
4. 既存の自治体title試験との重複を確認する。重複ページは除外するか既存試験の終了後に扱う。対象・対照・前28日の値を変更前に保存する。

### 修正の分岐

| 確認した課題 | 最初の修正 | 固定するもの |
|---|---|---|
| ページは意図に答えるが検索表示で内容が伝わらない | titleのみ | H1・description・本文・canonical・OG/Twitter |
| 意図への回答がページ内で見つけにくい | 冒頭要約または該当箇所の導線 | title・canonical・他の主要構成 |
| 検索意図と掲載データが合わない/根拠不足 | 修正保留 | 推計や新規データで埋めない |

全国版のtitle候補は実データの1位・掲載範囲・基準年を使う。候補を先に公開せず調査結果で採否を決める。自治体別変更もallowlistで限定し、共通テンプレート変更による全件波及を防ぐ。欠損値・出典・honesty表示を維持する。

### 評価・完了条件

titleは変更前28日と、公開翌日以降28日のページCTR・クリック・表示・順位を比較する。検索titleの反映遅れ、共通クエリ・デバイス構成を記録する。全国版は同等の対照を置きにくく、前後差を因果効果と断定しない。+0.3ポイントは旧計画からの採用候補目安で、単独の合否基準にはしない。

ページ内修正は該当導線のクリック/着地など対応する成果を測れる場合に限って評価する。検索CTRだけで本文修正の効果を判定しない。計測追加が必要なら、基準期間を先に確保する。

対象選定の理由、変更前後のHTML、実データとの整合、対象外ページへの非波及、観測結果を保存して完了とする。調査で根拠が得られなければ「変更見送り」も完了状態とする。
