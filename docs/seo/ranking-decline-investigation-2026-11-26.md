# 人口ランキングの順位低下と改善施策の調査

調査日: 2026-11-26 JST。対象: GSCの平均掲載順位の悪化、広告掲載との関係、人口ランキングの改善候補。

深掘り後の採否・対象・日程は[改善対応計画](ranking-response-plan-2026-11-26.md)を正とする。初回の福岡・兵庫両方に配置とSEOを順次適用する案から、福岡は操作導線、兵庫はSEO説明に対象を分けた。

平均掲載順位の悪化には、表示される検索語の構成変化と、一部の主要検索語の実際の順位低下が混在している。Googleの11月コアアップデートも同時期に実施されているため、広告を主因とは特定できない。登録障害や手動対策は対象ページでは見つからなかった。

利用上の具体的な改善点は確認できた。375px幅の福岡県ランキングでは、先頭10件と「11件目以降」の操作の間に縦長の実広告が入り、順位表の続きへ進むために広告を通過する必要がある。また、流入が増えた「県名 人口」という検索意図と、市町村の順位を答える現在のページには差がある。

本番の設定・コードは変更していない。アンケートは所有者の意図による停止として扱う。

## 原因の切り分け

### Googleのコアアップデートと期間が重なる

Google公式の11月コアアップデートは11/10 10:06〜11/24 06:03、US/Pacific。順位悪化の期間と重なる。11/24に掲載された12月コアアップデートの情報は予告であり、11/24に新たなアップデートが開始したという意味ではない。[11月の公式記録](https://status.search.google.com/incidents/WLxcJyC6jMWMfryxsKMc)、[12月の予告](https://status.search.google.com/incidents/AXrqxXXdtSjj3672ux7X)

広告掲載、11/16のランキング構成・広告配置・全幅対応、11/20の関連リンクや一部SEO変更が近接している。単純な公開前後比較から、それぞれの寄与率は識別できない。アップデートが当サイトの低下を引き起こしたという直接証拠もなく、重要な交絡要因として扱う。

Googleはアップデート完了後、少なくとも丸1週間の実績を待って比較することを勧めている。今回の順位変化は数位以内のものが中心で、全面的な作り直しより対象を絞った改善が適する。[Googleの評価手順](https://developers.google.com/search/docs/appearance/core-updates)

### 表示される検索語の構成が変わっている

11/11〜17と11/18〜24で、検索語・URL・端末・国が同じ返却行を比較した。共通5,288組の平均順位は通常の重みで6.50→6.84だが、後期間の表示回数の重みを前期間に固定すると6.08になる。両期間10表示以上の511組でも5.38→5.03で、構成を固定した集計は改善側だった。

これは、全体平均の悪化を「同じ検索語での一律の評価低下」と読めないことを示す。検索語の匿名化とページ単位の集計があるため、プロパティ全体の6.82→6.97への寄与率としては計算しない。

日本・モバイルの例:

|---|---:|---:|---:|---:|
|埼玉県 人口 → 埼玉県人口ランキング|4|215|3.00|10.07|
|福岡県 人口 → 福岡県人口ランキング|30|212|9.97|9.18|
|広島県 人口 → 広島県人口ランキング|37|209|9.76|9.72|

順位10位付近での一般的な「県の人口」の露出増が、表示回数を増やし平均順位・CTRを押し下げる一因になっている。これらの語は市町村の順位より県全体の人数を知りたい意図を含み得るため、ランキングの文言だけで対応しない。

### 登録障害と手動対策は確認されない

北海道・福岡・茨城・兵庫・長野・埼玉・岩手・愛知の8URLをURL Inspection APIで確認。すべてPASS、取得成功、robots許可、Google選定canonicalは自己URL。全件11/20以降のクロールが記録されている。

下落4県の本番HTMLも自己canonical・noindexなし。順位表は初期HTMLに北海道179行、福岡60行、茨城44行、兵庫41行を含む。11件目以降は閉じたdetails内にあり、クリック後にデータを初めて取得する構成ではない。アコーディオン自体はGoogleのスパムポリシー違反ではない。[Googleのポリシー](https://developers.google.com/search/docs/essentials/spam-policies)、[モバイルの本文に関する指針](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)

GSC管理画面では、手動による対策とセキュリティ問題はいずれも「問題は検出されませんでした」。これは対象4県の順位低下を未登録や手動ペナルティで説明する証拠がないという範囲であり、サイト全URLの品質を保証するものではない。

### 広告の表示性能への影響は未確定だが操作上の負担はある

11/21〜23の2026-11-20版、ランキングのモバイル計測では、CLSは良好1,357・要改善1・不良1イベント。LCPは良好2,599・要改善29・不良24、INPは良好1,492・要改善110・不良50だった。イベント分布であり、正確なp75や広告起因の劣化を示さない。旧計測版との単純なイベント数比較も行わない。

GSCのCore Web Vitalsは11/25更新時点でモバイル・PCともトラフィック不足。PageSpeed APIの福岡・兵庫へのリクエストは429 RESOURCE_EXHAUSTEDで、ラボスコアは取得できなかった。したがって「広告による性能問題なし」とは判定できない。

11/26の福岡県ページを375×667のiPhone SEエミュレーションで確認した。初回はPCで読み込んだ後に幅を変更した状態で、最初の画面に上位の順位が見え、広告は先頭10件の後にあった。実配信された1枠の広告は6商品を縦に並べ、11位以降の展開操作はその下だった。本文との重なりはこの1例では見られなかった。その後、モバイル幅を設定してから初回読込すると別の動画広告が配信され、広告後の操作で残り50件を開けた。広告の大きさは配信により異なるが、操作が広告の後にある構造は同じだった。それが検索順位を下げたという因果関係は未確定である。

Googleは本文を妨げる過剰な広告やモバイルでの広告配置の点検を勧めている。広告の有無だけでなく、必要な答えに進めるかを改善対象にする。[ページ体験](https://developers.google.com/search/docs/appearance/page-experience)、[モバイルの広告配置](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)

## 検索意図と競合から見た改善余地

検索で見つけた競合候補のページ構成を確認した。検索ツールの結果順をGoogleの現在順位とは扱わず、競合の過去順位や当サイトから奪ったクリックも推定しない。

「地域データ日本」の兵庫ページは、県全体の掲載人口、指標ごとの基準日、県の特徴、全市町村への導線を提供している。「地域の入れ物」の茨城ページは、冒頭にトップ3と各人口、人口の合計、住民基本台帳という定義を置いている。掲載年・統計系列が当サイトとは異なるので、人口値の差をそのまま誤りとは扱わない。[兵庫の構成例](https://japan-localstats.jp/hyogo)、[茨城の構成例](https://region-case.com/rank-2025-ibaraki-population/)

当サイトの福岡・兵庫・茨城は、冒頭の説明が「市区町村を、人口が多い順に並べたランキングです（国勢調査）」に留まる。表から人数は読めるが、統計の基準日、人口等基本集計、政令市と行政区の重複除外は短い説明として表の近くに揃っていない。出典は関連ランキング・ふるさと納税の案内より後の折り畳みにある。

候補は、一般的な解説の増量ではなく、対象件数・最多自治体と人数・最少自治体と人数・基準日・集計定義を現在の表と同じデータで答えること。県全体の人数を答える場合は、同じ統計・時点の県公表値か、欠損・重複を検証した集計を使い、収録自治体の合計を無条件に県の公式人口とは呼ばない。

タイトルも短く具体的にできるが、現在も「人口ランキング」の語と2025年国勢調査を含んでいるため、単語の追加だけを主施策にしない。2025年国勢調査を2026年人口と見せる変更はしない。[Googleのタイトル指針](https://developers.google.com/search/docs/appearance/title-link)

これらは改善候補であり、順位回復の保証ではない。配置変更と本文・タイトル変更は分け、変更日と版を記録する。アンカー広告追加、全県一括のtitle変更、本文の一括増量、canonical変更、人口ランキングの大量増設は今回の証拠から必要とは判断しない。

## 評価の時期

11/28は配信・操作・受信の中間確認に使う。コアアップデート完了後の11/25〜12/1の7日の確定・反映を待ち、12/4以降に更新前の同じ検索語・URL・端末・国と比較する。曜日を揃える参考期間は10/28〜11/3とし、11/3の祝日や検索需要の変化も併記する。12月アップデートが始まった場合は期間を分ける。

改善を公開する場合は、公開当日と運営確認を分け、翌日から14日で受信・不具合、28日でクリック・CTR・表示・順位と利用状況を確認する。少数ページの前後比較や同じ広告の他県ページを、ランダム化された対照実験とは呼ばない。広告停止テストを検討する場合も、まず同一条件のラボ・利用上の不具合から調べ、検索順位の回復だけで広告の因果効果を判定しない。

電気・備蓄の11/1〜28評価は別施策として12/1以降の予定を維持する。山口・島根の公開後28日評価も別に保持する。
